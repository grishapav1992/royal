# Установка на VPS

Текущая конфигурация переведена на единую PostgreSQL. Порядок миграции, права, копирование и откат: [Единая база PostgreSQL](POSTGRES.md). Исторические проверки SQLite ниже относятся к прежним выпускам. Фактическое переключение фиксируется в `deployment/SERVER.md`.

Для первого совместного теста: Linux VPS с 2 vCPU, 3 ГБ RAM, 45 ГБ SSD, публичным IPv4 и SSH-доступом. Это стартовая конфигурация, вместимость зависит от реального процессора, соседей по VPS и задержки сети. Подойдёт Ubuntu 24.04 LTS. Желательно выбрать локацию с небольшой задержкой до участников.

## Подготовка

1. Установите Docker Engine и Compose plugin по официальной инструкции для вашей ОС: https://docs.docker.com/engine/install/ubuntu/.
2. Создайте DNS-запись A для игрового домена, например `play.example.com`, на IPv4 сервера. Если настроена AAAA, она также должна вести на этот сервер.
3. Откройте TCP 80 и 443 в сетевом экране провайдера. SSH должен быть доступен администратору. Игровой порт 2567 напрямую наружу открывать не нужно.
4. Скопируйте проект на сервер без `node_modules`, `.env`, `dist`, `dist-server`, `test-results`, `data` и `artifacts`.

## Запуск

Из каталога проекта на сервере:

```sh
cp .env.example .env
```

Укажите реальное имя домена в `.env`: `SITE_DOMAIN=play.example.com` (без https и без завершающего слеша). Также задайте `PUBLIC_ORIGIN=https://play.example.com`. Затем:

```sh
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 game caddy
```

Caddy получает HTTPS-сертификат и направляет HTTP и WebSocket на игровой сервер. После получения сертификата откройте `https://play.example.com`. Войдите по почте и паролю, выберите персонажа, скопируйте приглашение и откройте его на другом устройстве с другим аккаунтом. Проверьте движение и обмен сообщениями в обе стороны. `/healthz` должен отвечать JSON с `ok: true`.

Для входа по паролю в production используется HTTPS. Локальная разработка допускает HTTP на localhost. Старый адрес по IP можно оставить в списке SITE_DOMAIN, приложение перенаправит браузер на PUBLIC_ORIGIN.

## Обновление и данные

После копирования новой версии повторите `docker compose up -d --build`. Обновление перезапускает игру и завершает текущие комнаты. Комнаты и сообщения хранятся только в памяти. Том `game_data` сохраняет аккаунты, сессии и выбранных персонажей в SQLite. Тома Caddy сохраняют сертификаты. Не используйте `docker compose down -v`, если нужно сохранить данные. Для резервного копирования SQLite используйте SQLite backup API либо остановите игровой контейнер на время копирования всех файлов базы. Один экземпляр сервера обслуживает все комнаты этого демо. Для нескольких экземпляров понадобится отдельная настройка маршрутизации и общего состояния.

Образы используют ветки Node 22 и Caddy 2. Docker-пакет нужно проверить на выбранном VPS; локальная проверка приложения не заменяет проверку HTTPS и WebSocket из внешней сети.
