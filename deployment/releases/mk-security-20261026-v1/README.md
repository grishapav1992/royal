# HTTP and Mortal Kombat security release

This release updates body-parser 2.3.0 to 2.4.0 and its required qs 6.16.0 to 6.16.1, rejects unnecessary compressed application bodies and sends a public combat projection with only the recipient's input acknowledgement. Fight rules, accepted stakes, common wallet storage and host contracts remain unchanged.

Prepare from a clean source commit already pushed to main with the shared release tools and the verified current production source as base. Run release:verify before prepare.py. The preparer checks every built byte, canonical source differences, the precise two-package lock transition and the installed decoder package trees. A separate production dependency cache is updated only for those two packages. The compatible combat module is published after the backend using the existing guarded independent module installer. Older clients retain compatible rendering and acknowledgements. Other module pointers, host contracts and backend programs remain unchanged.

The installer retains the three shared deployment locks and checks the complete current source, configuration hashes, all dependency bytes and symlink targets, running and prepared images, immutable client URLs, module state and other persistent service fingerprints. The image adds a single bounded overlay to the verified previous image. It does not install arbitrary packages on the server. All other dependency files and image settings must stay identical. The candidate repeats the delayed-gzip regression on its actual Node runtime without external networking or player data.

Before mutation, stream a source archive under a hard compressed-byte limit and create a bounded PostgreSQL game-wallet backup. Verify every archived source file, the dump format, previous index and rollback image tags. No full source staging copy is created. Preserve at least 5 GiB free and the explicit build margin before and after backup and build. The context uses hard links to the exact payload and is removed after verification.

Immediately before switching, a temporary Compose one-off obtains the same PostgreSQL advisory transaction lock used by combat funding. It waits for active combat and virtual PvP holds to reach zero. It then retains the financial lock while source files are installed and the old game container is replaced, preventing a new funded fight in the check-to-restart gap. A timeout before acquiring a quiet state leaves application source and runtime untouched. The gate has its own transaction and process deadlines. Durable game sessions, database contents, environment, mounts and other services are preserved.

Rollback verifies the same wallet sources and combat contract, restores only this release's source delta and selects the verified previous image. It never restores wallet data from a dump. If the running image never switched, rollback avoids a needless restart. An unrelated later publication prevents rollback. Record exact commit, image and independent public checks in SERVER.md and push the deployment record before considering publication complete.
