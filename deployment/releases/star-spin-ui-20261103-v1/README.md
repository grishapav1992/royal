# Star Spin: публикация интерфейса 1.5

Обновляется только `studio-wild-nudge`, пакет `1.5.0-dfaacbc6bb0f`, контракт API/rules/progress 1/2/1. Его манифест SHA-256 `1ddebb56a1b8331c1e488bff0075a8d5c75a9a005442cd170062fa6155fbbbe6` совпадает с [проверенной локальной версией](../../../docs/game-layout/star-spin/verification.json). Основной клиент, backend, математика, кошелёк, набор доступных игр, персонажи, звуковые и Rive-ресурсы сохраняются. Новый код кота из main в выпуск не включается.

`publish.py` использует прежний защищённый publisher независимых модулей и полный инвентарь работающего host. Под тремя штатными замками проверяются исходная версия, все программы, службы, настройки, указатели, контракты и доступное место. В рабочие исходники переносятся только шесть перечисленных файлов игры. Остальные входы пакета должны совпасть с production по точным или нормализованным LF-хешам; установленная Rive-зависимость допускается только с прежним точным SHA-256.

До переключения сохраняются проверенный архив прежних исходников и указателя, прежний пакет и тег текущего образа. Publisher проверяет весь новый пакет и атомарно заменяет только указатель Star Spin. Хост не перезапускается, базы и финансовые службы не изменяются. После установки полный инвентарь должен отличаться только шестью исходниками и файлами нового пакета.

`verify-inputs.mjs` независимо связывает восемь CRLF-входов Windows с прежними LF-байтами production. У `GameHostContract.ts` main добавлены только импорт типа и необязательное поле `flagToteClient`: esbuild выдаёт побайтово одинаковый JavaScript. Точные исходные и исполняемые хеши сохранены в `input-equivalence.json`. Игровая математика, вероятности и кошелёк не изменены; новые значения доказательств RTP не создаются этой проверкой.

Установка ожидает три замка. Совместимость после подготовки ограничена двумя уже сохранёнными в main выпусками: анимацией кота и удалением надписей зала `5538f71e3c1d61ebdd8e73a43a395dfcaec22a6e`. Между ними разрешён только точный SHA-256 `src/game/interiorArt.ts`. Изменение математики, настроек, финансовых программ, другого постоянного сервиса, указателей модулей, контрактов или целевых исходников Star Spin блокирует установку. По действующему образу выбирается его проверенный snapshot; полный свежий инвентарь до и после установки остаётся обязательным. Это позволяет сохранить параллельное обновление зала без пересборки неизменного игрового пакета. В записи различаются основа сборки и фактическая основа установки.

Сборка: штатные `release:plan`, `release:prepare --modules wild-nudge` и `release:verify --github` с последним проверенным исходником production. Пока ожидались замки, другой чат опубликовал анимацию кота: основа обновлена с `24cce094af9b39e008a31c3e5803436174e95a36` до `8616f86d5c31ee81abdcd18484de0d4c1a2446e4`. Этот выпуск сохраняется. Повторная подготовка использует тот же проверенный пакет; его байты менять нельзя. Предыдущие проверки UI и общего кошелька сохраняют силу только для совпадающих входов. После публикации обязательны публичная проверка байтов и завершённое штатное обслуживание.

Откат независимого клиента использует сохранённую версию `1.4.0-cb27b33abd7a` и проверку текущего указателя штатным publisher. Возврат исходников также требует сохранённого в main соответствующего изменения. Не восстанавливать базу, не менять правила принятых раундов и не удалять пакет, которым ещё пользуется открытая сессия.
