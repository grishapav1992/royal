# LAST EXIT

Original daytime Hollywood-style pursuit presentation for the existing `github-crash` game. The cabinet is named LAST EXIT. Its persistent game ID is retained so existing runs and the shared wallet continue to work. This is a presentation replacement for Crash, not an additional independent wallet or a second Crash entry.

The player chooses a stake, starts a two-second countdown, then takes the exit before the server's crash deadline. Reaching 100x pays automatically. Manual exit uses the server's accepted timestamp, a multiplier rounded down to a hundredth, and a payout floored to 0.01 coin. Late exits lose. Saved due runs settle on the next wallet or game request. The renderer never receives a future crash point and never extrapolates beyond the latest confirmed server timestamp.

The Crash generator, growth rate 0.06/s, cap, transaction locks, reservation, debit, payout and retry handling remain unchanged. The existing ideal fixed-target return is approximately 99% before rounding and network delays. No new RTP profile is claimed. Police, vehicle speed, route sections, background fire and decorative explosions contain no information about a future outcome and have no effect on payouts. There is no steering or automatic target cashout in this presentation.

Visuals: four original built-in image_gen assets, bright Californian afternoon highway, unbranded muscle coupe, patrol car and explosion. Composited Canvas chase with road motion, patrol movement, escape and impact sequences. No movie logos, actors, licensed music or neon treatment. Asset paths, provenance and full prompts are in the candidate's artwork.json. The early nighttime concept was discarded after the user requested daylight.

Audio: original Web Audio synthesis of engine harmonics, filtered road noise, pursuit siren, escape skid and impact. It uses the shared sound output and limiter, respects global volume/mute and the per-game sound toggle, unlocks after a user gesture and stops on page hiding. All owned sound sources stop and disconnect on destroy. Reduced motion removes camera motion, light pulses and the brief impact flash. Browser instrumentation verified active sound, zero RMS when muted and zero owners/sources after closing; physical speaker listening is not claimed.

RU/EN controls and rules, account-scoped local history of ten confirmed runs, recoverable pending actions and a large exit button. Narrow containers 320/390 px and the actual GameViewport shell were checked. These are desktop browser container checks, not physical phone or iOS verification.

Publication source base: verified live meme-ui-balance-20261019-v1, 884 qualified files. Only the twelve LAST EXIT paths are overlaid. Unpublished Orbit changes are excluded. All server sources, dependencies, wallet code, other games and the independent GIRLHUB package remain byte-identical to production. The two shared files change only the Crash renderer and cabinet presentation. Local preview fixtures and controlled clocks/outcomes are excluded.

Local preview: http://127.0.0.1:5198/last-exit-preview.html?review=1&lang=ru. It uses an isolated temporary PostgreSQL database and test accounts. Harness pages, fixtures and controlled crash/time overrides are excluded from qualified source and release archives. Production, real accounts, .env, Docker, persistent volumes and payment services were not modified. Publication needs a fresh production-base reconciliation.

Validation: four confirmed-time display tests, four PostgreSQL settlement tests, one real HTTP auth/settlement/replay test, a full production build and browser checks for exit, crash, lost replies, retry recovery, account switching, saved cap settlement, settings and audio disposal. Evidence is in the candidate's proof directory.

Post-review fixes (2026-10-19): a manual exit stays available during a background state read. The existing wallet client invalidates that read when it sends the exit, so a late active response cannot replace a settled run or its credited balance. Busy and pending POSTs still block repeat actions; starting a new run still waits for a state read. Live and crashed multipliers use the same floored integer hundredths as the exit quote. Already-paid multipliers are reconstructed with integer rounding to avoid flooring a serialized decimal a second time. These corrections do not alter server math, growth, rounding, deadlines or RTP.
