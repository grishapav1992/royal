# Mortal Kombat production release

Publishes the independent floor-2 cabinet, compatible host/backend and private Nile financial command handlers. Stakes use the existing shared test-network wallet. The committed RTP qualification covers all allowed stakes and decisive/refunded outcomes. No separate balance, deposit credit, signing key or financial microservice is introduced.

Prepare from a clean committed checkout already included in origin/main with the shared release:plan, release:prepare and release:verify commands described in docs/release-process.md. Use the verified running source commit as --base. Run bundle-finance.mjs in that same checkout: the financial bundle includes its dependency graph except the existing PostgreSQL driver. prepare.py consumes those exact application outputs, the financial input inventory and a fresh production snapshot. There is no mixed source tree or second project/dependency copy.

The installer holds the application, client-presentation and module publication locks. It verifies all live source, runtime, configuration and module fingerprints, makes and verifies source backups, saves the current client index, tags both previous images and creates a financial schema dump. It builds image overlays from the verified files without duplicating build contexts. The existing environment, Compose files, domains, mounts, player data and volumes are preserved.

A real read-only financial audit and three readiness checks over at least 90 seconds precede host publication. Old immutable package URLs remain available. Only the Mortal Kombat pointer changes unless a verified wallet contract transition requires the already reviewed common packages. A later source or module change rejects the release. Host failure restores its previous source, contract, pointer and image. The upgraded financial service remains available to refund orphan combat escrow; the database dump is never restored over newer transactions.

Public verification must check health, the exact active manifest and every packaged byte, a real host on desktop/phone with its chat, and rejection of browser settlement endpoints. Two-player gameplay, atomic funding, forged combat controls, repeated payout and reopen recovery are verified against an isolated synthetic Nile ledger. Running source, image identifiers, backup checksums and verification results are recorded in deployment/SERVER.md after publication. Retention keeps the current application and one verified rollback, with active-work and financial-backup exceptions.
