# CR vs. Leo: pitch perspective, stadium sound and net response

Release requested explicitly in this chat on 22 October 2026. Publish only the compatible `original-cr-vs-leo` module, version `1.0.0-a2ef09bbf7db`, and its qualified fifteen-path source delta. The host, character covers from the current main, other games, backend and persistent data remain intact.

The pitch uses shared projected geometry for the goal, stadium foot, both boxes and the 11, 20 and 30 metre shots. Stadium recordings provide neutral ambience, goal cheers and disappointment; each new goal plays the selected hero's short requested phrase. Audio uses the shared host output and preferences, cancels on close and reuses decoded recordings. Source pages and voice excerpt provenance are recorded in `docs/artwork/cr-leo-audio.json`. The net forms a local pocket, propagates a damped recoil and settles over 1.8 seconds while its anchors stay fixed. The ball reaches and briefly follows that same pocket.

`source-lock.json` pins source, build inputs, package files, helpers and the prior pointer. `production-comparison.json` compares the fresh production inventory with current main. Its protected historical server record and unrelated `server/LobbyRoom.ts.orig` backup are preserved. `deploy.py` holds both publisher locks, checks the complete production fingerprint, creates and verifies a source archive, tags both previous images, and atomically publishes only this module. A failure restores the pointer and changed source paths. The host container does not restart.

Validation covers the model, mesh geometry, actual rendered pixels, audio mixing and cancellation, isolated PostgreSQL wallet recovery, shared-wallet recovery across modules, publisher safeguards and automatic rollback. Guest browser checks use the real production host with the candidate package and the real chat integration helper with empty local content on desktop and mobile. They block production writes and do not create accounts, wagers, messages or a live chat connection. Publication results are recorded in `verification.json` and `deployment/SERVER.md` after the corresponding source commit has been pushed to main.
