# Qualified Neopolis and Dracona publication

Publish Neopolis rules/progress 3/3 and Dracona 3/2 with their qualified mathematics, the shared Nile journal and existing Royal window/chat. The host catalogue exposes Neopolis without moving cabinets. Original rules remain available for accepted rounds. No production stake, balance, reserve funding or database content is created by verification.

Build an LF Git archive of a pushed commit using `npm run build`, then bundle `scripts/finance-nile-play.ts` with only `pg` and `pg-native` external. Save its esbuild metadata as `artifacts/financial-meta.json`. Capture `snapshot.py` on the server after concurrent publications finish. `prepare.py STAGE SNAPSHOT OUTPUT COMMIT` verifies the source inventory, copies reviewed source and runtime deltas, and retains every previous immutable package. Neopolis and Dracona external pointers change. If the host is still on the previous demo-wallet transport, rebuild all already published pointers from the current main as well: their private wardrobe endpoints must move with the host. This preserves the newly published GirlHUB feedback and other concurrent changes instead of restoring old packages.

Upload the package into `/opt/royal-releases/neopolis-dracona-20261023-v1`. Run `deploy.py publish` only after its commit has been pushed to main. Both common publication locks stay held through guards, backups, builds, finance readiness and host installation. The installer refuses a changed baseline. Source, financial sources and journal backups remain on the server. It tags both previous game images and the financial image. Configuration, resources, mounts, domain settings, other services, external modules and persistent volumes are verified unchanged.

If the production dependency lock is older, the game image installs exactly the committed production dependencies, including the existing atelier runtime. This lets the qualified games integrate a partially published common-wallet release without using its stale source snapshot. The fresh source comparison and original configuration checks still apply. Dependencies of the financial bundle other than PostgreSQL are bundled into its reviewed output.

The financial update runs before the host and preserves the existing ledger. A failure stops publication and records its phase. Use a forward fix if users have accepted new Neopolis rounds; do not restore a journal dump or remove their compatible backend. Any recovery must be recorded and pushed under the production rules in AGENTS.md. Public verification checks both active pointers, every package file, host bytes, health and API authentication. Browser verification opens both production packages in the published host on desktop and mobile; transactional recovery uses a temporary database with the same committed server sources.
