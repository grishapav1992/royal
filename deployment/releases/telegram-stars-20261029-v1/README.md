# Telegram Stars owner probe

This scoped release installs only the payment service. It retains the existing host, all games, modules, unrelated dependencies, shared money ledger, payment event protocol, persistent data and unrelated services. The only proxy change is the public Stars webhook and terms prefix; existing team and NOWPayments routes remain intact. Caddy reloads its configuration without replacing its container.

Production fingerprinting found two older dependencies in the payment image: body-parser 2.3.0 and qs 6.16.0. The release updates only these packages to the committed lock versions 2.4.0 and 6.16.1 used by the verified application. Their portable JavaScript files are copied from the current installation, individually hashed and checked for retained obsolete files. Installed package metadata changes only for these two records. All other dependency files, versions and image metadata stay intact. The active payment program's complete external dependency graph is checked against the lock; unused image programs retain their original root package metadata and are not executed by this service.

Initial complete running-file inventories are retained for the exact immutable image ID only. Repeated checks may reuse that inventory only after Docker reports no overlay changes in any program path or its parent and no mount shadows any program path. Unknown images or changed program paths receive a fresh complete inventory. Candidate image bytes are always hashed in full before its inventory can be reused. Actual sources, settings, external modules, service identities and mount configuration continue to be checked on every snapshot. Mount ordering is normalized because Docker's output order is not a configuration change.

One-shot reader containers may disappear between Docker listing and inspection. Such missing temporary entries are ignored only when every protected persistent identity remains present; unexpected inspection failures and missing persistent services still abort. A preparation stopped before any financial installation can reuse its source backup only after exact checks of all saved source, archive contents, private settings and pinned rollback image. Any financial dump or recovery marker blocks this automatic retry. An already fully hashed candidate can receive a new source label without another file copy only when the expected inventory is identical and the resulting immutable filesystem layers and image process settings exactly match the verified candidate.

The exact application source and these helpers must be committed and pushed to main before canonical release preparation and `release:verify --github`. The installer payload contains the verified payments bundle, only its changed allowed source inputs and existing financial lease helpers. It refuses differing unrelated imported sources, installed dependency versions, runtime files, source fingerprints, service identities, configuration or module state. Preparation uses normal build outputs and a small task-owned payload, never a full source or dependency staging copy.

Upload the reviewed helpers to a fresh `/opt/royal-releases/telegram-stars-20261029-v1` folder. Run `python3 install.py snapshot` under the common publication locks and save its fingerprint in the local task folder. Generate the payload with prepare.mjs. Its manifest includes only hashes and public source metadata, without Telegram credentials or player records. Transfer exact prepared files, then run `python3 install.py release` with the filtered Telegram settings supplied privately on standard input. Account IDs and bot credentials must never be passed as command arguments, committed or included in the local payload.

Only one authorized account, a fixed 100-Star amount, one accepted checkout and a fixed 1-USDT credit are allowed. The separate payment service receives the Telegram credentials. Existing NOWPayments, withdrawals and real-money game flags must remain false. The current host receives the same signed payment events as before; its new Stars form is prepared in source but is outside this scoped installation. The probe invoice is created through the signed private payment API for the authorized account. The owner personally confirms its real payment in Telegram.

Before mutation the installer freezes the current state, saves changed source and private provider settings server-side, validates the proxy configuration, pins the prior payment image and creates a bounded PostgreSQL financial backup. It verifies the candidate's complete runtime inventory, holds all three publication locks and uses the existing supervised financial lease during installation. A failure writes a recovery marker and requires reconciliation of the actual running state. Never restore an old database over accepted money transactions or blindly rerun an operation with an unknown outcome.

After installation verify HTTPS terms and webhook authentication, bot identity, preservation of pending updates and the expected webhook destination before setting it. Verify the real successful receipt, exactly one payment ledger entry and one delivered game credit event, with the same internal USDT balance. Do not publish raw player details, charge IDs or private financial data in Git. Record the exact source commit, immutable image, retained backup hashes and aggregate verification in SERVER.md and push that record. Delete local payloads and screenshots and server task build contexts after verification; retain production rollback images and private financial backups.
