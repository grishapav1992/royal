# Faster native game entry

This release publishes a compatible client host and seven native packages together. It preserves the backend, bundled module baseline, installed host contract, production settings, volumes, other services, existing asset URLs and every retained independent package version. The seven target identities are Cosmic Escape, Caramel Carnival, Velvet Reign, Last Convoy, Nitro Run, GIRLHUB and Meme Overload.

Before publication, reconcile the release source against the complete production snapshot, validate the host and all seven packages, commit the corresponding source and push it to `origin/main`. The release manifest must identify that exact commit. Record public verification and the resulting image and package versions in `deployment/SERVER.md`, then commit and push that record.

The shipping directory contains `deploy.py`, `snapshot.py`, the reviewed `publisher.py`, `install-manifest.json`, `source/`, `dist-delta/` and `packages/<gameId>/`. The manifest uses the previous fast-entry schema (`release`, `sourceCommit`, `before`, `changed`, `delta`, `helperSha256`, `snapshotSha256`) and adds `publisherSha256` plus `modules`. Each `modules[gameId]` contains `version`, `expectedSha256` and `files`. `files` is the complete immutable package inventory, including `manifest.json`; `expectedSha256` is the reviewed external active pointer hash or `none` when the image baseline currently supplies the game.

Run `python3 deploy.py check`, `python3 deploy.py build` and `python3 deploy.py publish` from `/opt/royal-releases/game-entry-20261022-v1`. Both the application and module publication locks cover each operation. Build verifies a complete source archive, saves the prior index and target pointer bytes, tags the running and prepared images, and builds a small client overlay from the reviewed prior image. It does not duplicate the large existing `dist` tree. Full old program inventories and inherited image layers are verified before switching.

Publish installs only the reviewed source delta, starts the compatible host, waits for health, then invokes the existing publisher for each package with its reviewed prior pointer hash. Final verification requires exactly the old independent files, the seven selected immutable packages and their new pointers. Other external files and the private host contract must remain byte-for-byte unchanged.

On failure the helper restores the prior target pointers and source, selects the tagged prior image and restores the old index. A game with no previous external override returns to the preserved image baseline. Newly installed immutable versions remain available. Recovery refuses later images, later source changes, unrelated module changes and target pointers outside the reviewed old/new pair. A manual rollback also requires a corresponding source restoration committed and pushed to `main`; never restore old database contents or remove persistent volumes.

Run `python3 -m unittest discover -s deployment/releases/game-entry-20261022-v1 -p test_deploy.py` for local recovery checks. The tests cover partial publication, old-version tampering, changes to another game, a later target pointer, unrelated versions, restoration to a previous override or image fallback, and stale filesystem observations before any pointer is changed.

`source-lock.json` records the published source delta, immutable package inventories, selected versions and the retained public pointer evidence. It contains no environment values or user data. After performance profiles finish, verify public bytes with `node deployment/releases/game-entry-20261022-v1/verify-public.mjs --manifest deployment/releases/game-entry-20261022-v1/source-lock.json --output artifacts/game-entry-20261022/proof/public-assets-recheck.json`. Add `--dry-run` to inspect the plan without network requests. Do not overlap the bulk checksum downloads with performance measurements.

The browser profiler runs the actual host, walk, game window and chat in a clean guest context. A local debugger changes only the connection indicator to permit entry; all API writes are blocked, and authenticated saved-round latency is outside this measurement. Run `node deployment/releases/game-entry-20261022-v1/profile-game-entry.mjs --expected-entry index-C718g19b.js --versions deployment/releases/game-entry-20261022-v1/source-lock.json --output artifacts/game-entry-20261022/proof/public-entry-recheck.json`. Add `--games studio-afterglow,studio-nitro-run` or `--mobile 1 --inspect-intro 1` for the other sampled scenarios. Every invocation creates a new browser context; repeated opens inside it use normal browser caching. Timings include walking and vary with the network and computer. Use the recorded before/after game order for comparisons.
