# Casino Api Pro: подключение sandbox

Подключение использует существующий демокошелёк SQLite. Одна демомонета равна одной условной единице выбранной тестовой валюты, дробные суммы сохраняются точно до сотых. USDT Nile и финансовый сервис не участвуют.

## Доступ и ключи

1. Создай аккаунт на https://casinoapipro.com/signup и получи тестовые `ck_test_...` и `cs_test_...`. Пароль и ключи в чат не отправляй.
2. В проекте запусти `npm run casinoapipro:prepare`. Скрипт добавляет недостающие поля в локальный `.env` и сохраняет новый секрет callbacks, не выводя его. Существующие настройки сохраняются, файл имеет права 600.
3. Впиши ключи в `CASINOAPIPRO_API_KEY` и `CASINOAPIPRO_API_SECRET`. Валюта `CASINOAPIPRO_CURRENCY=USD` должна быть доступна аккаунту поставщика. `PUBLIC_ORIGIN` уже содержит адрес проекта.
4. Запусти `npm run casinoapipro:check`. Проверяются авторизация SANDBOX и каталог твоего аккаунта. Ключи, токены и адреса игровых сессий не выводятся.
5. Только после успешной проверки перенеси пять переменных `CASINOAPIPRO_*` в серверный `/opt/royal/.env`, сохранив его остальные настройки. Выставь `CASINOAPIPRO_ENABLED=true` и пересоздай только игру: `docker compose up -d --no-deps game`. Локальный `.env` целиком на сервер не копируй. Перед публикацией следуй SERVER.md.

## Кошелёк в кабинете поставщика

Developer → Wallet: среда `SANDBOX`, тип `REST`, статус `ACTIVE`. Выбери `HMAC_SIGNATURE` и укажи значение нашего `CASINOAPIPRO_WALLET_SECRET` как текстовый signing secret. Встроенный кошелёк типа SANDBOX использует отдельный баланс и для этой задачи не подходит.

В текущей форме кабинета выбери `My own wallet API`, Base URL `https://stealth-spark-gokmxooi.expresshost.cloud/api/casinoapipro/wallet/` и Paths `debit - relative to your base URL`. Завершающий `/` нужен, чтобы все пять относительных путей попали в наш адаптер. Authentication: `HMAC signature (recommended)`, Shared secret: значение `CASINOAPIPRO_WALLET_SECRET` без кавычек. Ввод и сохранение нового секрета в браузере выполняет пользователь.

Если Add wallet возвращает `a wallet integration with that label already exists for this environment`, открой Edit у существующего тестового кошелька вместо повторного создания. В проверенной форме при этом введённые настройки сохраняются, кнопка становится Save changes. Проверь среду Test Mode, тип REST, адрес и HMAC перед сохранением. Настройки LIVE не меняй.

При настройке через dashboard API альтернативный вариант: Base URL `https://stealth-spark-gokmxooi.expresshost.cloud` и полные пути из таблицы.

| Операция | Путь POST |
| --- | --- |
| balance | `/api/casinoapipro/wallet/balance` |
| debit | `/api/casinoapipro/wallet/debit` |
| credit | `/api/casinoapipro/wallet/credit` |
| refund | `/api/casinoapipro/wallet/refund` |
| rollback | `/api/casinoapipro/wallet/rollback` |

Сохрани стандартные camelCase имена входящих полей. Ответы: `balance`, `reference`, `duplicate`, код отказа `error_code`. Подпись проверяется по заголовкам `x-timestamp` и `x-signature`, точному исходному телу JSON и времени с допуском пять минут. Не выбирай NONE, BEARER или подпись webhooks.

Зайди в онлайн-зал, открой «Игры» → «Casino Api Pro» → «Настройка тестового доступа». Вставь показанный `royal_...` player ID и выбранную валюту в Test connection у поставщика. Один успешный подписанный запрос баланса подтверждает интеграцию для всех игроков. При смене ключа, секрета callbacks или валюты проверка сбрасывается. Новым игрокам вручную ничего настраивать не нужно.

## Проверка сценария

Пополнить наш демокошелёк, выбрать Casino Api Pro, открыть доступную игру. Баланс внутри игры должен совпадать с нашим. Сделать ставку и сверить её списание, выигрыш и итоговый баланс в истории демокошелька. Повторная доставка той же транзакции не меняет баланс. Пока ключи и Test connection не подтверждены, запуск закрыт.

Автотесты проверяют контракт на имитации поставщика. Настоящие игры и callbacks поставщика требуют отдельно пройти этот сценарий с его sandbox-аккаунтом. Live-дилеры в публичном каталоге не подтверждены. LIVE в документации означает среду реальных денег.

Источники: [test/live](https://casinoapipro.com/docs/test-and-live), [wallet API](https://casinoapipro.com/docs/wallet), [sessions](https://casinoapipro.com/docs/sessions), [OpenAPI](https://api.casinoapipro.com/openapi.json).

## Интеграция подтверждена: 7 октября 2026

В кабинете пользователь сохранил REST HMAC кошелёк SANDBOX с нашим адресом и относительными путями. Первый запрос после исправления секрета прошёл проверку подписи. Кнопка Test connection в текущем кабинете использует фиксированные `capro_connection_test` и GHS, поэтому наш USD-кошелёк вернул CURRENCY_MISMATCH. Для проверки конкретного игрока создана короткая сессия SANDBOX USD через официальный API, затем прочитано `/v1/game/state`: сам поставщик запросил наш баланс и получил `1000.00`. Диагностическая сессия закрыта без ставок. После этого `walletConnected=true`; защита запуска не отключалась, подписанный callback поставщика подтвердил сохранённую конфигурацию.

В публичном проекте тестовый игрок открыл Dice через карточку Casino Api Pro. Через интерфейс поставщика сделана одна ставка 1.00, выплата 1.94; наш журнал содержит отдельные списание до 999.00 и начисление до 1000.94. В игре и общем кошельке показан один и тот же баланс. Игровые состояния всех 14 доступных игр через короткие сессии независимо прочитали 1000.94 USD; эти проверочные сессии закрыты без ставок. Dice и Mines дополнительно проверены внутри iframe проекта.

Через операторский API SANDBOX проверены отдельная ставка 0.10, повтор того же transaction_id, полный возврат 0.10 и повтор исходной ставки после возврата. Повторы не добавили списаний или записей, последний повтор вернул исходный результат 1000.84, а текущий баланс сохранился 1000.94. Проверка добавила ровно две записи: ставку и её возврат. Выигрыш выше получен от игрового движка Dice, вручную он не задавался.
