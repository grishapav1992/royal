# Подключение к боевому серверу

В репозитории хранится [шаблон SSH-конфига](ssh_config.example) с вымышленным адресом и заменяемыми параметрами. Для подключения нужен приватный ключ, публичная часть которого разрешена на сервере.

Фактические адрес сервера, имя SSH-пользователя, порт и каталог приложения уточните у владельца сервера. Перед публикацией прочитайте [инструкции проекта](../AGENTS.md) и [журнал боевого стенда](SERVER.md).

## Локальная подготовка

Скопируйте шаблон в локальный файл, исключённый из Git:

```sh
cp deployment/ssh_config.example deployment/ssh_config.local
```

В `deployment/ssh_config.local` замените `server.example.invalid` на адрес сервера, `YOUR_SSH_USER` на разрешённого пользователя, `YOUR_PRIVATE_KEY` на имя вашего ключа в `~/.ssh/`. Если сервер использует другой порт, измените `Port`.

Приватный ключ хранится вне проекта. На новом компьютере доступ настраивается отдельно: владелец сервера должен разрешить публичную часть вашего SSH-ключа. Клонирование репозитория не переносит право доступа.

Ограничьте права на имеющийся локальный ключ:

```sh
chmod 600 ~/.ssh/YOUR_PRIVATE_KEY
```

При первом подключении получите отпечаток SSH-ключа сервера из доверенного источника, например консоли провайдера. Выполните команду ниже, сравните показанный отпечаток и подтвердите его только при совпадении. Проверенный ключ сервера сохранится в локальном `~/.ssh/known_hosts`.

```sh
ssh -F deployment/ssh_config.local -o StrictHostKeyChecking=ask -o BatchMode=no royal-production
```

При несовпадении или неожиданном изменении отпечатка сначала выясните причину у владельца сервера. Не отключайте проверку ключа сервера.

## Подключение

Все команды с конфигом выполняются из корня репозитория:

```sh
ssh -F deployment/ssh_config.local royal-production
```

Проверка состояния контейнеров без публикации, после замены `/PATH/TO/APP` на каталог приложения:

```sh
ssh -F deployment/ssh_config.local royal-production 'cd /PATH/TO/APP && docker compose ps'
```

## Что остаётся вне GitHub

Приватные SSH-ключи, пароли, токены, `.env` и содержимое баз данных не добавляются в репозиторий, архивы исходников и чат. `CODEX_SALE_API_KEY` хранится отдельно в локальном и серверном `.env`. Серверный `.env` не заменяется локальным: доменные настройки и рабочие данные сохраняются.

Перед публикацией нужны резервная копия исходников и тег предыдущего образа. Постоянные тома, включая `game_data`, сохраняются. Каждая опубликованная версия и результат её проверки должны быть зафиксированы в `royal` по правилам [обновления](README.md#обновление-и-данные).
