# Сердце леса: серверный раунд и общий кошелек v1

26 октября 2026 года. Сервер реализован, а после завершения клиента статус политики изменен на `qualified`. Правила и точный RTP [модели v1](rules-v1.md) сохранены. Клиент, игровые ресурсы, анимации и звук находятся в `games/forest-heart/`, игра зарегистрирована в каталоге Royal. Этот документ описывает серверную область; итог клиентских проверок находится в [verification.md](verification.md). На production игра не устанавливалась.

## Границы реализации

`server/games/forestHeart.ts` реализует start/move. `src/shared/forestHeart.ts` описывает протокол и пересчитывает показанную историю для проверки состояния и выплаты. `server/demoExpansion.ts` подключает движок к существующим общим сессиям и транзакциям кошелька. Новых таблиц баланса и отдельного финансового сервиса нет.

Основной маршрут действующего host: `/api/demo-wallet/expansion`, общий виртуальный USDT-кошелек `DemoWalletStore`. Он разделяет средства с PvP. Дополнительно сохранена совместимость `/api/game-wallet/expansion` через существующий финансовый процесс Nile. Проверка этого дополнительного маршрута не означает смену основного кошелька Royal.

Клиент должен передавать `X-Royal-Forest-Heart-Rules: 1`. Без него начало и продолжение отклоняются до генерации; чтение не возвращает серии этой игры. Это согласование поддерживаемых правил, а не средство авторизации. Владение серией проверяется по действующей авторизованной учетной записи. Старые команды финансового процесса без нового необязательного поля остаются допустимыми.

## Раунд и денежные операции

Начало принимает `gameId: studio-forest-heart`, `action: start`, новый UUID операции, `stakeUnits` из списка `1000, 2000, 5000, 10000, 20000, 50000` и строго `settings: {forestHeart: {mode: normal}}`. Все денежные значения представлены целыми сотыми общего USDT. Клиентские поля с выплатой, исходом или вероятностью отклоняются.

Состояния: `choice`, `bonus`, `settled`. Начальная ревизия равна 1. При наличии способности доступны `forest-pass` и `forest-turn-0` ... `forest-turn-11` в опубликованном порядке корней. В бонусе доступен только `forest-spin`. Каждый move содержит UUID, sessionId и текущую revision. Принятый ход увеличивает ревизию один раз; устаревший ход не генерирует случайность. Все продолжения имеют стоимость 0.

Ставка списывается один раз при start. Промежуточные цветы увеличивают итог внутри серии, но баланс до ее завершения не пополняется. При переходе в settled выполняется одно итоговое начисление, включая случай нулевой выплаты. Если способности и бонуса нет, серия завершается непосредственно в start.

Все действия используют существующую блокировку счета и одну транзакцию PostgreSQL: состояние, запись UUID, денежный журнал и резерв либо сохраняются вместе, либо откатываются вместе. Повтор того же UUID с тем же телом возвращает сохраненную серию с текущим кошельком и не выполняет ход заново. Измененное тело под тем же UUID отклоняется. При разных UUID и одной revision успешно проходит только один конкурентный ход. Незавершенную серию нельзя заменить новой ставкой этой игры.

Точный максимум выплаты равен 946,5 ставки. Общий механизм резервирования использует целочисленный множитель 947, консервативно покрывающий максимум. Эти дополнительные 0,5 ставки являются запасом емкости кошелька, не дополнительной выплатой и не изменением RTP. Пополнение или другое расходование общих средств не может занять зарезервированную емкость итогового начисления. После завершения резерв снимается.

## Случайность и восстановление

По умолчанию используется `node:crypto.randomInt`. Начало делает четыре независимых вызова с границами 4096, 10 000, 32 и 64: поле, энергия, способность и вход в бонус. Один ручной выбор не обращается к RNG. Каждый принятый бонусный move выбирает только очередное поле и энергию с границами 4096 и 10 000. Недопустимое значение RNG прерывает транзакцию.

Будущие бонусные поля и seed не генерируются заранее, не сохраняются и не передаются клиенту. В ответ входит только уже подтвержденная история и факт входа в бонус. В бонусной истории остаются эффективные поля с примененными закреплениями, без скрытых исходных битов закрепленных корней. Полная показанная история, сумма и закрепления проверяются повторным расчетом.

Серия сохраняет правила v1. Чтение после пересоздания хранилища возвращает тот же выбор или бонус без новой генерации. Потерянный ответ восстанавливается повтором исходной операции. При откате до подтверждения операция не принята; ее повтор может получить новый случайный результат. Закрытие и повторное открытие настоящего окна Royal также проверены на клиентском этапе.

## Квалификация и проверки

[Штатный отчет](../../game-math/qualifications/forest-heart-v1.json) получен командой `qualify:rtp` из реальных исходников, содержит их хеши и область `server-engine-and-primary-common-wallet`. Поле `clientVerification: separate-browser-report` явно отделяет проверку клиента от математического доказательства. Старое поле clientReady удалено, поскольку математический отчет не удостоверяет готовность интерфейса.

- Точный расчет всех 4096 полей, 13 доступных действий и полного четырехходового бонуса. Оптимальная стратегия дает 95,994233480111%; постоянный пропуск дает 93,077684967843%. Цель лучшей стратегии: 96% с допуском 0,2 процентного пункта. Это точные ожидания конечной модели, не выборочные оценки.
- Серверная сверка: 14 стратегий, 6 ставок, 2 независимых seed, 64 полных раунда на сочетание, всего 10 752. Все промежуточные и финальные выплаты сверяются с независимым расчетом графа. Эта выборка проверяет соответствие runtime модели, а не оценивает RTP редких исходов.
- Исчерпывающе проверены отображение всех 10 000 билетов энергии, 32 билетов способности, 64 билетов бонуса и 4096 начальных полей. Отдельно принудительно проверены все действия и максимальная полная выплата на каждой ставке.
- 11 сценариев на настоящем временном PostgreSQL: согласование клиента, конкурентные старты, повторы, сохранение выбора, приватность будущих исходов, владение, ревизии, бесплатный поворот, откат и повтор, все ставки и максимум, общие средства PvP, емкость выплат, неверная случайность и конфликт идентичности операции. Несколько свойств объединены в один сценарий. Синтетический журнал сверяется с независимо рассчитанными суммами и итоговыми остатками.
- Реальный HTTP проверяет авторизацию и Origin, потерю ответа, восстановление, чужую сессию, недопустимые поля, бонус и точное начисление. Дополнительный HTTP-тест проходит через финансовый socket Nile и проверяет его масштаб денежных единиц.

Быстрый gate повторяет точный расчет модели, проверяет полную матрицу доказательства и актуальные хеши. Он не запускает PostgreSQL заново при каждой сборке. Полная команда qualification запускает настоящий движок и денежные сценарии; CI содержит ее и серверные тесты. Изменение охваченных исходников требует повторной qualification. Критические математические и серверные файлы дополнительно закреплены в проверочном коде и требуют пересмотра этого кода при изменениях. Ручное редактирование proof для прохождения сборки запрещено.

```text
npm run analyze:forest-heart -- --verify
npm run test:forest-heart-math
npm run qualify:rtp -- --game studio-forest-heart --write-proof
npm run test:forest-heart-server
npm run check:rtp
npm run test:rtp-gate
node node_modules/typescript/bin/tsc --noEmit
npm run build
```

В локальной проверке также прошли денежные и совместимые тесты Неополиса, Драконы, HTTP перебалансированных слотов, общего виртуального PvP и native-games Nile. Интерфейс desktop/mobile с чатом, управление звуком и анимации проверены отдельно, см. verification.md.

Результаты серверного этапа: 9 математических тестов, 20 проверок RTP gate и 37 серверных/денежных тестов прошли; TypeScript и общая сборка успешны. Итоговая сборка после завершения клиента охватывает 118 модулей, включая Forest Heart. Штатное предупреждение Vite о размере общего JS chunk остается; оно не препятствует сборке.
