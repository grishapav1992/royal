# Знания проекта для разработки

«Мозги проекта» представляют собой общий серверный граф проверенных опубликованных компонентов и сохранённых знаний из Git. Он помогает перейти от темы или идентификатора игры к коду, проверкам, правилам и источникам. Оба компьютера читают один снимок по SSH. [Подключение и обновление общего хранилища](shared-project-brain.md).

Версия карты определяется работающей публикацией, а не последним `main` или HEAD компьютера. Хост, backend и независимые игровые модули могут происходить из разных коммитов. Компонент сохранённых знаний имеет свою проверенную Git-версию, связанную с установленной версией сервиса карты. Эти версии и частичное покрытие указываются явно. Для неопубликованной доработки доступен отдельный явный режим `--local`.

## Использование

```sh
npm run brain:status
npm run brain:query -- "кошелёк"
npm run brain:query -- "studio-forest-heart"
npm run brain:query -- "test:game-stakes"
npm run graph:explain -- "loadGameModule"
```

`brain:query` читает готовый общий снимок. Поиск идёт по названиям, идентификаторам и тексту сохранённых записей; вывод ограничен шестью записями и восемью связями каждой. Это текстовый поиск без смыслового перевода моделью. Для конкретных функций, импортов и более подробных путей используй [команды Graphify](graphify.md). Не найденная связь не доказывает отсутствие зависимости.

Для общего чтения требуются Node.js 24+ и разрешённый SSH-доступ. uv и Python на компьютере не нужны. Команды не перестраивают серверный снимок. При недоступности SSH, ожидающем обновлении, ошибке индексации или неподтверждённом runtime поиск завершается ошибкой без автоматического перехода к локальной карте. Только состояние `ready` подтверждает готовность снимка для проверенных компонентов; код 0 команды состояния сам по себе этого не означает.

Платные модели, ключи API и подключение к игровой базе для построения не нужны. Ни команды npm из исходников, ни квалификационные программы при индексации не исполняются.

## Какие связи создаются

- Структура кода: определения, импорты, вызовы и поддерживаемые анализатором межфайловые зависимости.
- Документация и YAML: заголовки, локальные ссылки, разрешимые упоминания кода и структурные связи конфигураций.
- Пакет игры: заявленный `gameId`, версии контракта, точка входа и файлы внутри пакета.
- Команда npm: объявление в `package.json`, явные ссылки на локальные файлы и другие команды этого пакета. Шаблоны путей сопоставляются с выбранными отслеживаемыми файлами.
- Математическая политика: обычный профиль, политика ставок, историческая версия или декларация бесплатной механики. Сохраняются ссылки на исходники правил, программу квалификации и доказательство. Это не новое подтверждение RTP; его проверяет штатный `check:rtp`.
- Знания из `ai-factory/project-knowledge/graph-seed.json`: сущности, отношения, исходные статусы и окружения, версия записи и ссылки на источники.

У каждого предметного объекта есть ссылка на файл, содержащий декларацию, и компонент. Связи включаются непосредственно в `graph.json` соответствующего снимка. Компактный `project-brain.json` хранит удобное для поиска представление тех же объектов, а не отдельную базу истины. Входные файлы, граф и индекс связаны контрольными суммами; обзор находится в `PROJECT_BRAIN.md`. Серверные снимки хранятся в `/var/lib/royal-project-brain`, локальные результаты явного `--local` находятся в игнорируемом `graphify-out/`.

## Как проверяются старые знания

Для каждого доказательства сравнивается записанный SHA-256 с доступным проверенным источником снимка. В локальном режиме используется текущий отслеживаемый файл. Результаты:

- `matches_recorded_hash`: текст совпадает с источником старой записи. Само утверждение заново не проверялось.
- `changed`: источник изменился. Вся запись получает `needs_review` и явную пометку «требует пересмотра».
- `not_indexed`: источник отсутствует в выбранных входных файлах. Запись также требует пересмотра.

Пересмотренные утверждения закрепляют также конкретные файлы кода и конфигурации. Поэтому последующее изменение этих файлов снова отмечает затронутое знание для пересмотра. `record_reviews` сохраняет дату, исходный коммит и версию каждой проверенной записи. Номер всего набора и дата непересмотренного факта показываются отдельно.

Старые хеши не заменяются автоматически. Отношения старого графа представлены как записи с отдельными ссылками на предмет и объект, поэтому наличие отношения не является свежей проверкой production. При первоначальной сверке 3 ноября 2026 обнаружены изменившиеся `deployment/finance/README.md` и `docs/github-games.md`. Затем [десять записей и связанные противоречия проверены по main](project-knowledge-review-20261103.md): уточнены формулировки, границы окружений и ссылки на конкретные исходники. Для пересмотренных записей сохраняются дата, исходный коммит и индивидуальная версия. Остальные записи сохраняют прежнюю версию знания; номер всего набора не означает повторную проверку каждого факта.

Карта не читает чаты, локальный журнал или серверную очередь Graphiti. Существующие [Graphiti и его обмен](../ai-factory/knowledge-graph/README.md) продолжают быть отдельным источником истории задач и решений. В этот снимок входят только знания, сохранённые в выбранных отслеживаемых файлах Git. Наличие пакета, теста, документа или старого отчёта о выпуске не является проверкой работающего сервера и не разрешает возвращать неактивные игры.

## Обновление и работа с двух компьютеров

После публикации штатное обслуживание проверяет фактический состав приложения и завершает обязательные проверки. Только завершённый проверенный запуск создаёт квитанцию состава компонентов и ставит обновление графа в очередь. Почасовое обслуживание повторно сверяет состояние, чтобы подобрать пропущенный запуск. Сервер строит снимок отдельно и заменяет активный указатель после проверки хешей и повторного подтверждения runtime. Неудачная индексация сохраняет предыдущие файлы, но не выдаёт их как актуальные для изменившейся публикации. Один `git push` не запускает обновление production-графа.

Перед доработкой на любом ПК обнови реальные рабочие файлы по [обычному процессу Git](development-workflow.md). Общие запросы всё равно используют серверный снимок; полученный новый код не переписывает знания о production. На втором компьютере достаточно получить клиентские скрипты из Git и настроить собственный разрешённый SSH-ключ вне проекта. Копировать снимки и приватные ключи между ПК не требуется.

Для анализа ещё не опубликованных изменений явно запусти локальный режим:

```sh
npm run brain:build
npm run brain:status -- --local
npm run brain:query -- --local "новая доработка"
```

`brain:build` является алиасом `build --local` и никогда не обновляет сервер. Локальному режиму нужен uv. Его `current` означает совпадение карты с этим checkout, включая изменения отслеживаемых файлов. Это не означает свежий `git fetch`, тесты приложения или проверку production.

В Git сохраняются генератор, правила, проверенные знания и документация. История исходников остаётся в GitHub. Для добавления новых высокоуровневых знаний нужен источник и проверка утверждения, а не только новая связь по сходству названий. У сохранённых знаний сохраняется собственная версия: совпадение хеша не подтверждает утверждение заново. Наличие установленного игрового пакета не разрешает включать его в активный каталог или принимать новые раунды.
