# Общие бесплатные спины

Политика `location-levels-v3` сохраняет XP, пороги уровней, количества и номиналы v2. Каждые пять уровней игрок получает пакет общих спинов и одну генерацию скина с двумя вариантами на выбор. Первый пул `royal-slots-v1` разрешает только Royal Coins и Royal Fruits, правила 1. Эти две существующие игры доступны через каталог существующих автоматов Royal. Дополнительных физических мест нет.

## Поведение игрока

В обычном окне игры есть выбор «Платная игра» либо бесплатный номинал с общим остатком. Пакеты одного номинала суммируются для показа, но сервер сохраняет каждую исходную выдачу. Сначала расходуется первый доступный пакет этого номинала. Пакеты разных номиналов не обмениваются друг на друга. Например, пять спинов по 0.50 можно разделить на три Coins и два Fruits.

Выбранный бесплатный номинал сохраняется в пределах вкладки и аккаунта при переходе между играми. Нулевой остаток останавливает игру. Следующий платный раунд требует явного выбора платного режима. Неопределённый результат блокирует новую операцию, а кнопка проверки повторяет прежний UUID в первоначальной игре. Закрытие окна, обновление страницы, смена игры или проигрыш не возвращают уже использованное право.

Выплата поступает в существующий общий виртуальный кошелёк. Денежной ставки нет, XP за бесплатный раунд нет. Генерации скина используют прежний механизм ателье. Бонусные продолжения в правилах Coins/Fruits отсутствуют.

## Ресурсы и расширение

- Выдача остаётся ресурсом `free_spins`. Определение содержит ровно одно назначение: прежний `gameId` либо новый неизменяемый `poolId`. Обработчик награды поддерживает оба варианта. Условия уже выданных прав не переписываются.
- В `progression_rewards` добавляется nullable `pool_id`. Для общего пакета `game_id` пустой, для исторического пакета `pool_id` отсутствует. Внешние ответы используют соответствующее именованное поле.
- Список игр пула и версии правил задаются на сервере и в общем каталоге. Клиент передаёт выбранный `gameId`, идентификатор пакета и UUID операции. Номинал, число спинов, владелец, RNG и выплата определяются сервером.
- В `progression_spin_uses` сохраняются первоначальный запрос, результат и финансовый отпечаток. Первичный ключ `(account_id, operation_id)` связывает UUID с пакетом и выбранной игрой. Изменение любого назначения при повторе вызывает конфликт.
- Общая транзакция с блокировкой аккаунта проверяет право, лимиты и вместимость кошелька, определяет исход, уменьшает остаток, зачисляет выплату и сохраняет квитанцию. Ошибка любого шага откатывает всё. Блокировка действует между процессами и играми, а не только внутри браузера.
- `ProgressionClient` принадлежит host и передаётся модулям через общий мост. Модули не создают собственные кошельки или очереди финансовых операций. Обновлённые пакеты требуют совместимого host с этим мостом; host устанавливается первым.

Новая игра сначала получает математическую квалификацию полного раунда для каждого допустимого номинала, включая бонусы и выборы игрока. Затем добавляется новая версия пула и политика выдачи. Старую опубликованную версию пула нельзя незаметно расширять. Для будущих бонусных игр бесплатное продолжение должно принадлежать исходному принятому раунду и не расходовать следующий подарочный спин.

## Повторное использование и накрутка

Авторизация, проверка владельца, запрет дополнительных полей и область текущего аккаунта применяются в API. Сервер принимает XP только из собственных подтверждённых расчётов платных раундов и собственных ставок PvP. Депозиты не начисляют XP, возвраты не учитываются, подарочные раунды не запускают новую цепочку наград. Уникальный milestone не позволяет повторно выдать подарок за тот же уровень.

Кроме ограничения HTTP, действует долговечный предел 120 новых принятых бесплатных раундов за минуту на аккаунт. Он общий для всех игр, вкладок и backend-процессов. Повтор уже принятой операции восстанавливается до проверки этого предела, переключателей и исчерпания пакета. Лимит не меняет вероятности или выплаты. Права нельзя передавать другому аккаунту. Аудит проверяет остатки, исходные выдачи, владельцев, назначение игры, номинал, результаты и финансовые отпечатки квитанций.

Это защита от подмены запросов, повторного расходования и повторной выдачи. Она не устанавливает, принадлежат ли разные аккаунты одному человеку. Отдельная политика мультиаккаунтов и сговора требует достоверных признаков и проверки; общий IP сам по себе для блокировки недостаточен. Существующий баланс и расчёты остаются виртуальными. Переход на реальные деньги требует отдельной интеграции источника средств и финансовой квалификации.

## Версии и экономика

v1 и v2 остаются неизменными для принятых ранее источников и выданных прав. Первое включение v3 допускается только после проверки отсутствия закреплённых за прежними политиками игроков под барьером записи. На предварительном production-аудите таких игроков нет; проверка повторяется непосредственно при установке. Если они появились, установка останавливается: нужна явная миграция с сохранением принятых раундов и прежних наград. Приложение не сбрасывает прогресс и не переводит существующие когорты автоматически.

При свободном выборе игры бюджет рассчитывается по наибольшему допустимому математическому ожиданию: 97% номинала у Fruits против 96% у Coins. Полная дорожка содержит 260 спинов с номиналом 4832.50 и максимальным ожидаемым полным погашением 4687.525 виртуальных единиц. На каждом префиксе сохраняется предел 4% зачтённого оборота. Это оценка затрат спинов, а не прибыль казино и не совокупный RTP. Расходы двадцати генераций считаются отдельно по фактической цене провайдера. Участие в игре с более высоким допустимым возвратом является разрешённым выбором игрока.

Проверки: конкурентный последний спин из двух соединений, переходы между играми, потеря ответа и перезапуск, подмена игры/пакета/номинала, владение, общий лимит, сохранение старых прав, нулевое списание и отсутствие XP. Браузерные проверки проходят в настоящем host с подключённым чатом на desktop и mobile. Публичные проверки не создают production-аккаунты, ставки, сообщения или генерации.
