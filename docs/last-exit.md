# LAST EXIT

Original daytime Hollywood-style pursuit presentation for the existing `github-crash` game. The cabinet is named LAST EXIT. Its persistent game ID is retained so existing runs and the shared wallet continue to work. This is a presentation replacement for Crash, not an additional independent wallet or a second Crash entry.

The player chooses a stake, starts a two-second countdown, then takes the exit before the server's crash deadline. Reaching 100x pays automatically. Manual exit uses the server's accepted timestamp, a multiplier rounded down to a hundredth, and a payout floored to 0.01 coin. Late exits lose. Saved due runs settle on the next wallet or game request. The renderer never receives a future crash point. Its live counter projects elapsed time between server replies; only the server confirms an outcome and paid multiplier.

The Crash generator, growth rate 0.06/s, cap, transaction locks, reservation, debit, payout and retry handling remain unchanged. The existing ideal fixed-target return is approximately 99% before rounding and network delays. No new RTP profile is claimed. Police, vehicle speed, route sections, background fire and decorative explosions contain no information about a future outcome and have no effect on payouts. There is no steering or automatic target cashout in this presentation.

Visuals: four original built-in image_gen assets, bright Californian afternoon highway, unbranded muscle coupe, patrol car and explosion. Composited Canvas chase with road motion, patrol movement, escape and impact sequences. No movie logos, actors, licensed music or neon treatment. Asset paths, provenance and full prompts are in the candidate's artwork.json. The early nighttime concept was discarded after the user requested daylight.

Audio: original Web Audio synthesis of engine harmonics, filtered road noise, pursuit siren, escape skid and impact. It uses the shared sound output and limiter, respects global volume/mute and the per-game sound toggle, unlocks after a user gesture and stops on page hiding. All owned sound sources stop and disconnect on destroy. Reduced motion removes camera motion, light pulses and the brief impact flash. Browser instrumentation verified active sound, zero RMS when muted and zero owners/sources after closing; physical speaker listening is not claimed.

RU/EN controls and rules, account-scoped local history of ten confirmed runs, recoverable pending actions and a large exit button. Narrow containers 320/390 px and the actual GameViewport shell were checked. These are desktop browser container checks, not physical phone or iOS verification.

Publication source base: verified live meme-ui-balance-20261019-v1, 884 qualified files. Only the twelve LAST EXIT paths are overlaid. Unpublished Orbit changes are excluded. All server sources, dependencies, wallet code, other games and the independent GIRLHUB package remain byte-identical to production. The two shared files change only the Crash renderer and cabinet presentation. Local preview fixtures and controlled clocks/outcomes are excluded.

Local preview: http://127.0.0.1:5198/last-exit-preview.html?review=1&lang=ru. It uses an isolated temporary PostgreSQL database and test accounts. Harness pages, fixtures and controlled crash/time overrides are excluded from qualified source and release archives. Production, real accounts, .env, Docker, persistent volumes and payment services were not modified. Publication needs a fresh production-base reconciliation.

Validation: four confirmed-time display tests, four PostgreSQL settlement tests, one real HTTP auth/settlement/replay test, a full production build and browser checks for exit, crash, lost replies, retry recovery, account switching, saved cap settlement, settings and audio disposal. Evidence is in the candidate's proof directory.

Busy and pending POSTs still block repeat actions; starting a new run still waits for a state read. Live and crashed multipliers use the same floored integer hundredths as the exit quote. Already-paid multipliers are reconstructed with integer rounding to avoid flooring a serialized decimal a second time. These corrections do not alter server math, growth, rounding, deadlines or RTP.

## Боковой таран, уточнение 20 октября 2026

Патруль использует отдельные четыре фотографических ракурса поворота на дороге. Нос направлен внутрь, передний бампер касается боковины на 0.4 секунды, затем входит в силуэт панели при резком боковом толчке до 0.68 секунды. До контакта бампер не пересекает кузов. Колёса патруля остаются на той же дороге; второй патруль отходит наружу. Искры и короткий удар камеры совпадают с тяжёлым звуком удара. Поворот кузова, семь касаний в перевороте от камеры и последующий взрыв сохранены.

Первый нападающий выбран по публичному ID раунда, каждый следующий новый проигрыш использует противоположную сторону. Последние 64 раунда запоминаются в сессии интерфейса: перерисовка и повторное открытие того же результата не меняют атакующий патруль. Победы и текущая езда не расходуют последовательность. Это исключительно визуальное состояние, без влияния на расчёт, сроки и выплаты. Галерея использует независимый выбор для принудительного просмотра обеих сторон.


## Трамплин, самолёт и упрощение патруля, 20 октября 2026

В таране используются только первые три кадра patrol-ram.png: задний, небольшой поворот и поворот на 50 градусов. Четвёртый почти боковой кадр исключён из активной анимации. Последовательность сторон и контакт бампера сохранены. Из игрового логотипа LAST EXIT удалена декоративная точка.

При подтверждённом выходе выше 2.00x трамплин появляется у горизонта раньше самолёта. Камера слегка отдаляется в первые 0.55 секунды, чтобы кузов не закрывал дальний трамплин. Трамплин без растворения растёт в проекции дороги. Самолёт входит в кадр с 1.15 секунды и занимает позицию до 2.9. Машина заезжает на трамплин с 3.05 секунды, сходит с его края на 3.5, приземляется на грузовую рампу на 4.55 и проезжает в тёмный отсек до 5.05. Кузов непрозрачный, ограничен верхом проёма и уменьшается с расстоянием. После посадки его положение и масштаб связаны с самолётом. Вылет начинается на 5.25, вся связка оказывается вне экрана к 8 секундам. Трамплин проходит под камерой после прыжка. Звуки прибытия, отрыва, посадки и вылета используют общий таймер.

Порог <=2.00x для вертолёта сохранён. Всё изменение относится к Canvas 2D и подписи, расчёт раунда, кошелёк и сервер не менялись. Проверены 23 клиентских теста, включая видимость трамплина над кузовом до самолёта, непрерывность отрыва, размеры проёма и полный уход за край на шести размерах. Фактические кадры и запись находятся в proof/cargo-review локального кандидата.

Промзона: контейнеры и электропоры; развязка: бетонные опоры и шевроны; шоссе: металлический отбойник, камни и сухой кустарник; побережье: пальмы и кипарисы. ## Cashout acceptance delay

LAST EXIT cashout requests wait 200 ms on the server before the wallet transaction. The race continues during this interval. The multiplier and crash deadline are checked at acceptance after the wait; a crash during the wait loses. Concurrent retries of the same operation share the wait and retain the existing ledger idempotency. Other games and starting a round have no added delay. Normal pending requests add no recovery caption; failed requests retain recovery controls.

## Loading and continuous counters, 27 October 2026

The stage stays behind a loading screen until all 16 route, vehicle and ending images have downloaded, decoded and been drawn through the canvas image path. Progress counts decoded images. A failed or timed-out image keeps new runs blocked and offers a retry; closing cancels outstanding loads and prevents late completion from reviving the scene. The cinematic clock and its audio cues do not advance during preparation, so the first loss retains its intercept, depth rollover and explosion. An already accepted active run retains its cashout and operation recovery controls while artwork loads.

The numeric clock now advances one millisecond per local millisecond within already confirmed server time. A 700 ms presentation buffer (two normal polling intervals) absorbs ordinary reply jitter. Normal replies extend the confirmed boundary without resetting the visible position or applying a catch-up acceleration. A long interruption still freezes at that boundary. If a new confirmation is more than two buffers ahead, the display resynchronizes to one buffer behind it, preventing stale quotes for the rest of the run. A confirmed settlement replaces the buffered display immediately. Reduced motion uses the same numeric clock. Decorative speed is shown to one decimal place. Server growth, deadlines, cashout acceptance, rounding, stake handling and settlement are unchanged. The buffer is an engineering choice for this polling cadence, not a measured perceptual threshold.
