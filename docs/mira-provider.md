# Провайдер диалога Миры

MiraService поддерживает codex.sale Responses и Venice Chat Completions. По умолчанию MIRA_PROVIDER=codex-sale. Для Venice задайте MIRA_PROVIDER=venice, VENICE_API_KEY и VENICE_NPC_MODEL=venice-uncensored-role-play в серверном .env. Ключи не коммитить. Точный каталог доступен через GET https://api.venice.ai/api/v1/models.

Для Docker добавьте compose.mira.yaml последним к существующему списку Compose-файлов. На production список из метки работающего контейнера дополняется этим файлом, а COMPOSE_FILE в серверном .env сохраняет полный список для последующих запусков. Не заменяйте прежние overlays и .env. Сервис game получает ключ; клиент его не получает. Модерация общего чата продолжает использовать codex.sale.

Venice получает собственный системный образ Миры, историю, память и подтверждённое игровое опьянение. Встроенный образ Venice и веб-поиск выключены, ответ ограничен JSON-схемой. При ошибке, усечении или неверном ответе память не обновляется. Диалог автоматически не отправляется другому провайдеру.

Исходники выпуска mira-venice-20261020 фиксирует deployment/releases/mira-venice-20261020/source-lock.json. Выпуск меняет только backend и добавляет overlay. Клиент, финансовые программы, зависимости и независимые модули берутся из прежнего работающего образа. Для воспроизведения берётся gitBase, применяются productionPins (если есть) и sourceDelta из коммита выпуска; хеши всех входов должны совпасть с source. Окончательная основа включает опубликованный LAST EXIT от 20 октября 2026.

## Язык разговора

Мира поддерживает все опубликованные языки игры: русский и английский. Клиент передаёт выбранный язык в Accept-Language; сервер также понимает региональные варианты и приоритеты этого заголовка. Ответы, варианты реплик, приветствия и служебные сообщения используют выбранный язык.

Память принадлежит аккаунту и общая для обоих языков. Переключение сохраняет факты, отношения, отказы от напитков, историю в исходном виде и действующую паузу разговора. Оно не считается новым посещением. Старые записи памяти читаются без миграции; язык последнего ответа определяется для первого переключения.
