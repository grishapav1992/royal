# Провайдер диалога Миры

MiraService поддерживает codex.sale Responses и Venice Chat Completions. По умолчанию MIRA_PROVIDER=codex-sale. Для Venice задайте MIRA_PROVIDER=venice, VENICE_API_KEY и VENICE_NPC_MODEL=venice-uncensored-role-play в серверном .env. Ключи не коммитить. Точный каталог доступен через GET https://api.venice.ai/api/v1/models.

Для Docker добавьте compose.mira.yaml последним к существующему списку Compose-файлов. На production список из метки работающего контейнера дополняется этим файлом, а COMPOSE_FILE в серверном .env сохраняет полный список для последующих запусков. Не заменяйте прежние overlays и .env. Сервис game получает ключ; клиент его не получает. Модерация общего чата продолжает использовать codex.sale.

Venice получает собственный системный образ Миры, историю, память и подтверждённое игровое опьянение. Встроенный образ Venice и веб-поиск выключены, ответ ограничен JSON-схемой. При ошибке, усечении или неверном ответе память не обновляется. Диалог автоматически не отправляется другому провайдеру.

Исходники выпуска mira-venice-20261020 фиксирует deployment/releases/mira-venice-20261020/source-lock.json. Выпуск меняет только backend и добавляет overlay. Клиент, финансовые программы, зависимости и независимые модули берутся из прежнего работающего образа. Main уже содержит неопубликованный вариант LAST EXIT; для воспроизводимой сборки текущего production его прежние файлы сохранены в productionPins. Для воспроизведения берётся gitBase, применяются эти файлы и sourceDelta из коммита выпуска; хеши всех входов должны совпасть с source. Не публикуйте неопубликованные изменения LAST EXIT при обновлении только Миры.
