# Карта проекта Graphify

Graphify помогает находить связи между исходниками, тестами и документацией. Используется официальный пакет [graphifyy](https://github.com/Graphify-Labs/graphify), закреплённый на версии 0.9.101. Это локальный инструмент разработки. Он не входит в приложение и не запускается на игровом сервере.

Существующий [Graphiti](../ai-factory/knowledge-graph/README.md) хранит проверенные факты, решения и результаты задач. Graphify дополняет его автоматически извлечёнными связями исходников. Карта исходников не подтверждает публикацию возможности или доступность игры.

## Запуск на каждом компьютере

Нужны Node.js и [uv](https://docs.astral.sh/uv/getting-started/installation/). Обновлять глобальный `graphify` или устанавливать skills не требуется. Первый запуск через uv получает закреплённый Graphify и Python 3.12, если подходящего Python ещё нет. Далее окружение и кеш повторно используются. Обычные npm-зависимости проекта для карты не нужны.

```sh
npm run graph:build
npm run graph:status
npm run graph:query -- "DemoWalletStore"
npm run graph:explain -- "PostgresDatabase"
npm run graph:path -- "DemoWalletStore" "PostgresDatabase" --undirected
npm run graph:affected -- "PostgresDatabase" --depth 2
```

`query` возвращает ограниченную часть графа, по умолчанию до 2000 токенов. Точные имена символов и пути обычно полезнее общих вопросов. Для русского текста участвует обычное текстовое совпадение; смыслового перевода вопроса моделью нет. При неоднозначном имени Graphify перечисляет варианты и возвращает код 3; используй указанный ID. Код 4 означает отсутствие результата. Отсутствие пути не доказывает отсутствие зависимости.

Перед `query`, `explain`, `path` и `affected` проверяются содержимое входных файлов, версия инструмента, текущий коммит и контрольная сумма графа. Устаревшая или повреждённая карта перестраивается. `graph:status` ничего не строит: код 0 означает `current`, код 1 означает `missing` или `stale`. `graph:build` явно перестраивает карту, повторно используя кеш разбора отдельных файлов. Одновременные сборки блокируются файлом `graphify-out/build.lock`. Если процесс аварийно завершился, проверь записанный PID и удали только оставшийся без процесса lock.

## Входные данные

Список берётся из индекса Git, содержимое читается из текущих рабочих файлов. Учитываются изменения отслеживаемых файлов, удаления и переименования. Новый файл попадает в карту после `git add`. Это действие только добавляет файл в индекс, коммит не требуется. Посторонние неотслеживаемые файлы и локальные копии с суффиксом «2» не сканируются. Символические ссылки не индексируются.

Разбираются TypeScript, JavaScript, Python, Go, shell и Markdown. `package.json` и `tsconfig*.json` участвуют в проверке актуальности, поскольку влияют на разрешение импортов. Исключены зависимости, сборки, игровые медиа, `artifacts`, данные, секреты, локальное состояние Graphiti, исторические пакеты `deployment/releases` и дубли справочника в `ai-factory/project-knowledge/references`. Исторические документы в остальных отслеживаемых каталогах остаются источниками с их собственными датами и оговорками.

Также локально разбираются YAML-конфигурации. В проверку актуальности включены сохранённый seed знаний, RTP-политики и файлы квалификаций. [Предметный слой знаний](project-brain.md) добавляет в тот же граф явные связи пакетов, команд, политик и исторических записей с источниками. Он не меняет правила игр, доказательства квалификации или журнал Graphiti.

Используется структурный API Graphify: AST для кода и детерминированный разбор заголовков, ссылок и разрешимых упоминаний кода для Markdown. Это не смысловой пересказ документов. Связи отмечены `EXTRACTED`, `INFERRED` или `AMBIGUOUS`. Выводы об архитектуре и области изменения проверяй по самим исходникам. Динамические регистрации, маршруты, SQL внутри строк и обращения через сеть могут требовать дополнительного поиска.

Некоторые скрипты и тесты представлены только узлом файла: анализатор не выделяет в них символы. Их количество показано в отчёте. Найденный путь через общий импортирующий файл означает структурную связь, а не доказанную цепочку исполнения. Для точной проверки читай указанные строки и выполняй соответствующие тесты приложения.

Процесс Graphify получает ограниченное окружение без ключей провайдеров. `GRAPHIFY_BACKEND=none` отключает модельные backend; `.env` не читается. Обновление глобальных skills и журнал запросов Graphify выключены. Платные API, облачный Graphify, PostgreSQL, игровые данные и синхронизация Graphiti не используются. При первой установке uv загружает публичные пакеты; последующие запросы используют локальную карту.

## Результаты и проверка

В игнорируемом `graphify-out/` находятся:

- `graph.json`: направленный граф Graphify с версиями схемы и пакета, коммитом и источниками.
- `GRAPH_REPORT.md`: краткие счётчики, типы доказательств и наиболее связанные символы.
- `royal-manifest.json`: хеши входных файлов и графа, коммит, время и длительность сборки.
- `cache/`: восстановимый кеш разбора файлов.
- `project-brain.json` и `PROJECT_BRAIN.md`: компактный предметный индекс и обзор со статусами источников сохранённых знаний. Хеш индекса также проверяется перед его использованием.

Файлы карты не включаются в Git и Docker. На втором компьютере карта строится из его текущего checkout. При ошибке извлечения или изменении исходников во время сборки предыдущая карта сохраняется; поиск завершается ошибкой, пока актуальную карту не удастся построить. В таком случае можно продолжать обычное исследование исходников.

```sh
npm run test:graphify
```

Эти проверки охватывают выбор отслеживаемых файлов, исключение локальных и чувствительных файлов, изменение состава карты, определение устаревания и повреждения, а также отсутствие ключей в окружении инструмента. Проверять пользовательские сценарии следует также настоящими запросами к карте и чтением найденных исходников. Измеренная экономия времени или контекста пока не установлена.
