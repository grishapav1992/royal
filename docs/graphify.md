# Карта проекта Graphify

Graphify помогает находить связи между исходниками, тестами и документацией. Используется официальный пакет [graphifyy](https://github.com/Graphify-Labs/graphify), закреплённый на версии 0.9.101. Обычные команды читают один серверный граф проверенной production-версии. На каждом компьютере не нужно хранить и обновлять свою копию этой базы. [Настройка общего графа и порядок обновления](shared-project-brain.md).

Существующий [Graphiti](../ai-factory/knowledge-graph/README.md) хранит проверенные факты, решения и результаты задач. Graphify дополняет его извлечёнными связями исходников. Связь в графе и наличие опубликованного пакета не подтверждают доступность игры или разрешение новых раундов.

## Общие запросы с любого компьютера

Нужны Node.js 24+ и разрешённый SSH-доступ к серверу. uv и Python на компьютере для этих запросов не требуются. Клиент запускает фиксированную серверную программу, передаёт ограниченный JSON через SSH и не открывает публичный порт. На другом ПК используется тот же серверный снимок со своим SSH-ключом вне Git.

```sh
npm run graph:status
npm run graph:query -- "DemoWalletStore"
npm run graph:explain -- "PostgresDatabase"
npm run graph:path -- "DemoWalletStore" "PostgresDatabase" --undirected
npm run graph:affected -- "PostgresDatabase" --depth 2
npm run graph:god-nodes -- --top 10
```

`query` возвращает ограниченную часть графа, по умолчанию до 2000 токенов. Параметр `--budget` принимает значения от 128 до 4000. `affected` принимает `--depth` от 1 до 5 и до десяти `--relation <тип>`. `path` принимает `--directed` или `--undirected`, `god-nodes` принимает `--top` от 1 до 50. Произвольные флаги, пути вывода и `--graph` в общем режиме запрещены.

Точные имена символов и пути обычно полезнее общих вопросов. Для русского текста участвует обычное текстовое совпадение; смыслового перевода вопроса моделью нет. При неоднозначном имени Graphify перечисляет варианты и возвращает код 3; используй указанный ID. Код 4 означает отсутствие результата либо явно указанную ошибку проверки production. Отсутствие пути не доказывает отсутствие зависимости.

В ответе показаны выпуск, идентификатор снимка, отпечаток опубликованных компонентов и коммит этого ПК. Они могут различаться: `main` и рабочие файлы могут уже содержать ещё не опубликованные изменения. Хост, backend и независимо опубликованные игровые модули также могут происходить из разных коммитов. Проверяй конкретный компонент и версию источника, прежде чем сопоставлять результат с локальным файлом.

`graph:status` ничего не строит. Смотри поле состояния: только `ready` означает готовый снимок для подтверждённых компонентов. Успешное выполнение команды состояния само по себе не означает `ready`. При `missing`, `pending`, `failed`, неподтверждённом runtime, повреждении данных или ошибке SSH обычный поиск завершается ошибкой. Предыдущий снимок сохраняется для защиты от сбоя, но не выдаётся как актуальный после смены production. Автоматического перехода к локальной карте нет.

Обновление начинается после завершённого проверенного обслуживания публикации. Почасовое обслуживание сверяет пропущенные изменения. Коммит или `git push` сами по себе общий граф не обновляют. Подробности и диагностика описаны в [инструкции общего графа](shared-project-brain.md).

## Локальная карта для неопубликованной доработки

Явный `--local` переключает команду на рабочие файлы этого компьютера. Для этого режима нужны [uv](https://docs.astral.sh/uv/getting-started/installation/) и Node.js 24+. Первый запуск через uv получает закреплённый Graphify и Python 3.12, если подходящего Python ещё нет. Затем окружение и кеш используются повторно. Обычные npm-зависимости проекта для карты не нужны.

```sh
npm run graph:build
npm run graph:status -- --local
npm run graph:query -- --local "NewWalletSymbol"
npm run graph:affected -- --local "NewWalletSymbol" --depth 2
```

`graph:build` и `brain:build` являются алиасами `node scripts/graphify.mjs build --local`. Они всегда строят только временную карту рабочей копии. Прямой `node scripts/graphify.mjs build` без `--local` отклоняется. Общий серверный граф этими командами не изменяется.

Перед локальным запросом проверяются входные файлы, версия инструмента, текущий коммит и контрольные суммы графа и предметного индекса. Устаревшая или повреждённая локальная карта перестраивается. Локальный `status` возвращает код 0 для `current` и 1 для `missing` или `stale`. Это сравнение с рабочей копией, а не подтверждение свежего `git fetch`, тестов или production.

Список локальных файлов берётся из индекса Git, содержимое читается из рабочих файлов. Учитываются изменения отслеживаемых файлов, удаления и переименования. Новый файл попадает после `git add`; коммит для локального анализа не требуется. Посторонние неотслеживаемые файлы и символические ссылки не индексируются. Следуй [порядку разработки](development-workflow.md), чтобы не анализировать случайно устаревшую рабочую копию.

Одновременные локальные сборки блокируются `graphify-out/build.lock`. После аварийного завершения проверь записанный PID и удали только оставшийся без процесса lock. При ошибке извлечения или изменении исходников во время сборки предыдущая карта сохраняется, а запрос завершается ошибкой. Обычное исследование исходников можно продолжать без карты.

## Связи и границы доказательств

Разбираются TypeScript, JavaScript, Python, Go, shell, Markdown и YAML. Структурный API Graphify использует AST для кода и детерминированный разбор заголовков, ссылок и разрешимых упоминаний кода для Markdown. Это не смысловой пересказ документов. Связи отмечены `EXTRACTED`, `INFERRED` или `AMBIGUOUS`. Динамические регистрации, маршруты, SQL внутри строк и сетевые обращения могут требовать отдельного поиска.

Некоторые скрипты и тесты представлены только узлом файла: анализатор не выделяет в них символы. Путь через общий импортирующий файл означает структурную связь, а не доказанную цепочку исполнения. Для точной проверки читай соответствующую версию исходников и выполняй подходящие тесты приложения.

Сервер использует подтверждённый состав опубликованных компонентов и их исходники, проверенные по хешам. Если точное исходное представление компонента недоступно, покрытие помечается как частичное; ссылки на найденные исходники не превращаются в полную карту исполнения. Сохранённые знания и инструкции имеют отдельно указанную Git-версию. [Предметный слой](project-brain.md) связывает пакеты, команды, политики и исторические записи, сохраняя их собственные статусы.

В локальном режиме `package.json`, `tsconfig*.json`, сохранённый seed знаний, RTP-политики и JSON из `src`, `server`, `docs/game-math` и `deployment/qualifications` участвуют в актуальности карты. Исключены зависимости, сборки, игровые медиа, `artifacts`, данные, секреты, локальное состояние Graphiti, исторические пакеты `deployment/releases` и дубли `ai-factory/project-knowledge/references`. Исторические документы сохраняют свои даты и оговорки.

Процессы получают ограниченное окружение без ключей провайдеров. Модельные backend, журнал запросов и автоматические изменения глобальных skills выключены; `.env` не читается. При первой подготовке runtime uv получает публичные пакеты. Платные API, игровые данные и синхронизация Graphiti для карты не используются.

## Результаты и проверка

Общий граф хранится на сервере в `/var/lib/royal-project-brain`. Завершённый снимок содержит `graph.json`, `project-brain.json`, `PROJECT_BRAIN.md`, манифест хешей и происхождение компонентов. Указатель на текущий снимок заменяется атомарно после проверки; предыдущий завершённый снимок сохраняется. Клиент получает ограниченный текстовый ответ и происхождение, а не копию базы.

В игнорируемом локальном `graphify-out/` находятся `graph.json`, `GRAPH_REPORT.md`, `royal-manifest.json`, `project-brain.json`, `PROJECT_BRAIN.md` и восстановимый кеш разбора файлов. Эти файлы не включаются в Git и приложение.

```sh
npm run test:graphify
npm run test:shared-brain
```

Проверки охватывают выбор файлов, исключение чувствительных данных, актуальность, целостность, разделение версий компонентов, публикацию снимков и строгий SSH-протокол. Проверять пользовательские сценарии следует также реальными запросами и чтением найденных исходников. Измеренная экономия времени или контекста пока не установлена.
