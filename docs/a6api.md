# Доступ к a6api с нескольких ПК

Ключ провайдера хранится только на сервере в `/etc/royal-a6api/key` с правами 0600. В Git находятся клиент и серверный обработчик, без ключа. Сервер выполняет запросы к `https://api.a6api.com` через SSH. Отдельного публичного порта и доступа через игровой аккаунт нет.

## На каждом ПК

1. Получить актуальный `main` по `docs/development-workflow.md`.
2. Настроить собственный доступ по SSH к `root@45.192.12.242`. Это отдельное право доступа к серверу: чтение репозитория GitHub само по себе его не даёт. Секретный ключ другого ПК копировать не требуется. Если на втором ПК ещё нет доступа, оператор добавляет его публичный SSH-ключ обычным способом.
3. Проверить отпечаток сервера при первом обычном подключении SSH. Клиент требует уже известный сервер и не принимает новый отпечаток автоматически.
4. Выполнить `npm run a6api -- models`. Команда получает каталог моделей без запроса платной генерации.

По умолчанию используется `~/.ssh/royal_server_ed25519`. При другом имени ключа задать переменную окружения `A6API_SSH_KEY` с полным путём. `A6API_SSH_TARGET` меняет пользователя/сервер для установки с другим SSH-доступом. Эти переменные читаются из окружения процесса, локальный `.env` для клиента не нужен. Нужны Node.js и команда `ssh` (OpenSSH есть и для Windows). Установка npm-зависимостей этому клиенту не требуется.

## Использование из приложений

Запустить `npm run a6api -- serve`. Пока команда работает, локальный адрес API: `http://127.0.0.1:8766/v1`. Если приложение обязательно требует поле API key, указать `royal-local`: это локальная заглушка, сервер подставляет настоящий ключ самостоятельно. Настоящий ключ приложение не получает.

Поддерживаются список моделей, Chat Completions, Responses, генерация и редактирование изображений, embeddings, речь, транскрипция и Messages. Доступность конкретной модели и метода определяется a6api и условиями ключа. Поддержка маршрута не обещает, что он включён у провайдера. Потоковые ответы и бинарные файлы передаются без преобразования. Авторизация, cookies и другие заголовки локального приложения на upstream не отправляются. Для Messages сервер задаёт `anthropic-version: 2023-06-01`.

Прямой запрос из JSON-файла: `npm run a6api -- request /v1/responses input.json`. Для ввода из stdin вместо имени файла указать `-`. Для сохранения точных байтов без служебных строк npm использовать `node scripts/a6api.mjs request /v1/responses input.json > output.json`. Запросы генерации расходуют общий баланс a6api согласно условиям провайдера. Наш клиент и шлюз не повторяют запросы автоматически. В подключаемом приложении или SDK также отключить собственные автоматические повторы платных запросов. При обрыве соединения сначала проверить результат у провайдера, прежде чем повторять.

Локальный шлюз слушает только `127.0.0.1`, отвергает браузерные Origin/Sec-Fetch-Site и посторонние Host, не включает CORS. Он предназначен для доверенных локальных программ. Лимиты: 32 MiB на запрос, 128 MiB на ответ, четыре одновременных запроса на локальный шлюз и общий таймаут около 330 секунд. Произвольные адреса, редиректы, биллинг и управление ключами не проксируются. При таймауте или ошибке SSH клиент не повторяет запрос.

## Установка и проверка оператором

`deployment/a6api/install.mjs` устанавливает точные проверенные исходники из коммита, уже включённого в `origin/main`. Ключ передаётся только через stdin зашифрованного SSH и сохраняется отдельно от исходников. Повторная установка не заменяет существующий ключ другим без явного операторского действия. Старый обработчик сохраняется как непосредственный откат.

Первоначальная установка: `node deployment/a6api/install.mjs <source-commit> <absolute-path-to-local-env>`. Локальный env используется только для первоначального переноса одного `A6API_KEY`, остальные настройки не передаются. После успешной серверной проверки локальную строку `A6API_KEY` можно удалить. Обновление уже установленного обработчика: `node deployment/a6api/install.mjs <source-commit>`, без локального env и ключа. Сохраняется существующий серверный ключ. Серверный игровой `.env` не меняется.

Это установка отдельного операторского инструмента. Игровое приложение, Docker-образы, каталог, кошелёк и правила не пересобираются и не публикуются. Вместо манифеста приложения установщик проверяет точные Git-байты обработчика, фиксирует SHA-256 и коммит в `/opt/royal-a6api/manifest.json`, удерживает штатные три замка, проверяет текущий контейнер и запас 5 GiB. После установки обязателен завершённый проход штатного обслуживания и запись в `deployment/SERVER.md`.

Проверки: `npm run test:a6api` и `python3 -m unittest discover -s deployment/a6api -p 'test_*.py'`.
