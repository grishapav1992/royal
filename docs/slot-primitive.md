# Slot Primitive: подключение к Royal

[Автономный шаблон](../templates/slot-primitive/README.md) отделяет визуал от подтверждения ставок и раундов. Он не копирует Royal и не заменяет существующий [Slot Kit](slot-kit.md). В «Пути дракона» используется тот же порт с адаптером общего виртуального кошелька.

## Паттерн: порт, адаптер и внедрение зависимостей

`SlotServicesV1<View>` задаёт порт к источнику подтверждённых данных: мок для автономной копии или [адаптер Royal](../src/modules/RoyalSlotServices.ts) поверх `GameHostV1`, общего кошелька и `ExpansionClient`. Визуал получает только чтение состояния, [фасад `SlotActionsV1`](../templates/slot-primitive/src/actions.ts) и, опционально, набор обработчиков `SlotPresentationActions`. Он не знает URL, ключей, хранилища или UUID транспорта.

### Команды и реакции

- `bet(draft)` отправляет обычную ставку. `playFree()` продолжает подтверждённый раунд без доплаты, `recover()` проверяет прежнюю операцию, `refresh()` читает снимок.
- `bet` и `free` как события означают, что соответствующая команда подтверждена. Адаптер Royal связывает результат обычного старта с UUID отправленной операции, а бесплатный ход с ID раунда и следующей ревизией. Обновление и восстановление не повторяют события.
- `loss`, `partial`, `return`, `win` и `bigwin` относятся к **итогу оплаченного раунда**, а не к отдельному каскаду или фриспину. Множитель крупного выигрыша задаёт визуал конкретной игры. Фасад сравнивает уже подтверждённые суммы для выбора реакции, не рассчитывает выплаты и не начисляет деньги.
- В [«Карибских сокровищах»](../games/caribbean-treasures/feedback.md) используется такое же разделение: команда отправляется в общий клиент, а реакция, звук и анимация выбираются по подтверждённому результату. Эталонный визуал принимает обработчики явно и передаёт им `AbortSignal` для остановки эффекта. Действующие модули не меняются.

### Добавление новой механики

Новая механика не требует править общее ядро, если она только меняет картинку или добавляет бесплатный ход:

1. Опишите подтверждённые данные в своём `View`: например, позиции собранных предметов или последовательность кадров. Добавьте сценарий с фиксированными входами и ожидаемым экраном. Для визуала держите данные типизированными, а не универсальным словарём событий.
2. В `binding.project(session)` преобразуйте нужную версию серверной сессии в этот `View`. `freeMoves(session)` разрешает конкретные ID бесплатных команд и допустимые значения выбора. Адаптер пересекает этот список с актуальными `session.view.actions`, проверяет нулевую цену, выбор, ID и ревизию до вызова транспорта.
3. Если появились новые финансовые полномочия, например покупка бонуса, добавьте отдельную capability с подтверждённой полной ценой, явным действием игрока и собственными тестами. Не расширяйте `playFree()` для платных запросов. Изменение расчёта остаётся в backend.

Механику можно вынести в файл игры и импортировать как `Pick<RoyalSlotBinding<MyView>, 'project' | 'freeMoves'>`. В точке сборки объедините её с `gameId`, `rulesVersion` и `ordinaryStart`. Для этого этапа композиция нескольких функций проще, чем общий реестр плагинов или шина произвольных событий. Новая версия порта нужна только когда меняется смысл существующих действий или обязательных полей, а не при добавлении нового типа анимации в конкретную игру.

## Покрытие механик

Сверка проведена по исходникам [Caramel](../src/shared/caramelCarnival.ts), [Luelon/Velvet/Cosmic](../src/shared/luelonSlots.ts) и [Caribbean](../src/shared/caribbeanTransport.ts), не по активному production-каталогу.

| Механика | Что даёт каркас |
| --- | --- |
| Обычный спин, ставка, подтверждённый раунд, восстановление | Через существующий Royal транспорт. При pending новой операции нет. |
| Фриспины, респины и бесплатный выбор | `playFree` привязывает ход к снимку. Зависит от того, какие команды действительно принимает backend конкретной игры. |
| Линии и геометрия барабанов | Конструктор, импорт/экспорт JSON, подсветка на стенде. Произвольные линии не отправляются в backend. |
| Ways, кластеры, каскады и удержание | Сценарии и примеры полей представления: высоты, позиции, кадры, падения и удержанные символы. Пример Caramel преобразует уже подтверждённые каскады. |
| Скаттеры, множители, коллекции | Мок показывает подтверждённые значения и состояния. Стандартный визуал не моделирует все частные эффекты. |
| Покупки, платные режимы, выбор числа линий игроком, прогресс между раундами | Не подключены. Настройки и прогрессию подключайте в адаптере игры; платным действиям нужен отдельный контракт. |
| RNG, выигрыш, таблица выплат, RTP | Не входят. Ни стенд, ни адаптер не рассчитывают исход. |

## От копии до модуля Royal

1. Используйте `templates/slot-primitive/` как корень нового Git-репозитория. Оставляйте смысл `SlotServicesV1` одинаковым; меняйте визуал и данные сценариев отдельно.
2. Для согласованной игры перенесите визуал, `view.css` и ресурсы в `games/<slug>/` либо импортируйте общие компоненты. Не включайте `demo-services.ts`, редактор, HTML и глобальные стили стенда в пакет игры со ставками. Типы берите из общей копии контракта в Royal. Укажите метаданные и ресурсы по [контракту модулей](game-modules.md).
3. В `games/<slug>/entry.ts` экспортируйте `gameId`, `apiVersion`, `rulesVersion`, `progressVersion`, `mount`. В `mount` соберите `services = createRoyalSlotServices(readGameHost(), binding)`, затем передайте визуалу `services`, `createSlotActions(services)` и обработчики эффектов темы. [Пример Caramel Carnival](../src/modules/SlotPrimitiveCaramelExample.ts) показывает подключение фасада, сохранённый результат и кадры каскадов. Он не предназначен для замены действующей Caramel, которая также обрабатывает покупки и исторические раунды.
4. `ordinaryStart` возвращает только настройки. Адаптер повторно определяет полную стоимость для этих настроек штатными функциями Caramel, Cosmic, Velvet и Caribbean с общей ставкой на линии. Неизвестные настройки и любая цена, отличающаяся от выбранной ставки, не отправляются. Адаптер требует `manualStakes: 1` и использует общие пресеты и точный парсер. Несовместимый снимок, в том числе завершённый, блокирует новый старт. Клиентский пакет исполняется в контексте хоста: подключайте только проверенный код через штатную сборку, не произвольный внешний URL.
5. Если это новая игра, зарегистрируйте её в `GameModuleCatalog.ts`, общем backend и [политике ставок и RTP](game-stakes.md). Перед публикацией нужны проверка кошелька и реального окна с чатом на десктопе и мобильном, разрешение на добавление игры и штатный релиз. Сборка клона никого не добавляет в каталог.

### Пример прямого переноса: «Путь дракона»

[Модуль «Путь дракона»](../games/panda-dragon/README.md) открывается штатным загрузчиком и сохраняет окно Royal с общим чатом. Точка входа задаёт заголовок через контекст хоста. `mountPanda` принимает снимки, команды фасада и общую аудиосистему. Язык, допустимые ставки и переход между пресетами берутся из Royal; собственное оформление не зависит от приложения Lovable. Для React подписка перечитывает состояние по уведомлению; провайдеру не обязательно возвращать тот же объект из `read()`.

**«Путь дракона» использует общий виртуальный кошелёк, без сценарного сервиса.** Точка входа проверяет совместимость хоста и внедряет `createRoyalSlotServices` с привязкой к подтверждённому снимку. Визуал разрешает только серверные бесплатные действия. [Правила, совместимость и квалификация](game-math/dragon-path-v1.md) проверены локально. На боевой сайт эта игра не выкатывалась.

Автоигра в Royal живёт над тем же фасадом: [контроллер серии](../src/ui/slotKit/SlotAutoplay.ts) считает только подтверждённые платные вращения, а [привязка игры](../games/panda-dragon/usePandaAutoplay.ts) дожидается показа поля, бесплатного этапа, ручного выбора и подтверждения итога бонуса. Порт переносимого шаблона и серверный расчёт не пришлось расширять.

## Локальные проверки

Сначала соберите шаблон и прогоните его сценарии:

```bash
npm --prefix templates/slot-primitive test
```

Проверка адаптера и реального `ExpansionClient` с подставленным сетевым ответом:

```bash
node --import tsx --test server-tests/slot-primitive-adapter.test.ts
```

Браузерный тест находится в шаблоне и не использует исходники или зависимости Royal. Установите Chromium Playwright по инструкции в README либо запустите с установленным Chrome:

```bash
SLOT_BROWSER_CHANNEL=chrome npm --prefix templates/slot-primitive run test:browser
```

## Выгода и издержки

В небольшом изолированном репозитории AI получает только контракт, визуал и повторяемые исходы. Для серии тем на общей механике не нужно поднимать Royal, копировать его данные или снова писать восстановление кошелька. Одна и та же фикстура делает сравнение визуалов воспроизводимым, а контроль интеграции остаётся в Royal.

Цена: у каждого репозитория свои ресурсы, обновления и выпуск. Если разнести копии механик и контракта, поддержка станет дороже монорепозитория. Для новых визуалов, прототипов и независимых команд выгоднее внешний шаблон с закреплённой версией порта. Для мелкой правки одной существующей игры проще остаться в `games/`. Для новой механики экономия касается визуала, а не реализации правил, финансовой проверки и RTP. Измеренной экономии пока нет.
