# Пакет воспроизведения

Формат 1 связывает набор аудита, идентификатор пакета и сущности, категорию, профиль, режим и версии игры, правил и движка. Пакет принимает уже подтверждённые данные от адаптера игры. Адаптер отвечает за интерпретацию игровых полей, действительное состояние, связь проводок с сущностью и полноту наблюдения.

Манифест фиксирует начальное состояние, диапазоны порядковых номеров и времени, ожидаемые контрольные суммы фрагментов, охват и ссылку на финальное событие с его SHA-256. Событие может содержать подтверждённое действие, контрольное состояние или итог. Время событий задаётся в миллисекундах относительно начала пакета. При полном охвате номера идут подряд с единицы, последнее событие содержит итог. При частичном охвате причины пропусков перечисляются явно. Если не пришёл ожидаемый фрагмент, чтение возвращает его порядковый номер. Сведения об отсутствующих игровых действиях остаются пробелом исходных данных.

Контрольная сумма считается по JSON в UTF-8 с лексикографическим порядком ключей объектов. Порядок элементов массивов входит в контрольную сумму. Поле `sha256` исключается из данных при вычислении контрольной суммы самого манифеста или фрагмента. Контрольная сумма проверяет целостность полученного пакета. Источник и игровую семантику подтверждает адаптер.

Профили допускают только фиксированные поля. Казино сохраняет видимые игровые позиции и выбранные действия, пошаговый PvP использует места участников и позиции на поле, PvP в реальном времени использует тики, флаги управления и состояния бойцов, тотализатор использует номера участников и этапы. В схемах отсутствуют поля для аккаунтов, переписки, токенов и скрытой случайности. Лимиты формата составляют 128 фрагментов, 128 событий на фрагмент, 256 КиБ на фрагмент и 8 МиБ на пакет.

Хранилище принимает манифест, затем фрагменты в любом порядке. Точное повторение безопасно. Новые записи разрешены только в активном наборе с совпадающим окружением, ссылки проводок должны присутствовать в этом наборе. После закрытия набора чтение и точные повторы ранее принятых записей доступны. Неизвестная комбинация формата, режима, правил и движка выдаётся как неподдерживаемая. Список доступных версий передаёт вызывающий код. Для перехода к середине пакет использует ближайшее проверенное контрольное состояние и последовательность записанных событий до выбранной точки.

Формат 2 добавляет денежные строки с точными суммами и исходными ключами, квитанцию точности расчёта казино и события подключения для PvP. При `timing: 'source-order'` доступен только подтверждённый порядок. Нулевые значения `atMs` в таком пакете не означают одновременность. Прежние пакеты формата 1 читаются по прежней схеме.

Адаптер казино собирает пакет из подтверждённой операции или сессии и сохраняет его через хранилище. Выгружаются доступные принятые шаги, состояние и исход, точные списания и выплаты. При отсутствии надёжной истории ревизий или снимка на границе закрытия указывается пробел. [Адаптер казино](../../server/audit/replay-casino.ts)

Для шахмат записываются принятые сервером ходы, состояние доски, подключение, отключение и подтверждённый исход. Запись связывается с проверенными проводками банка выбранного набора. В тестовом контуре сбор включается параметром `ROYAL_AUDIT_CHESS_REPLAY=1` вместе с настройками аудиторского набора. Наблюдения незавершённой партии находятся в памяти комнаты. [Адаптер пошагового PvP](../../server/audit/replay-pvp-turn.ts)

Для платного боя запись формата 2 фиксирует изменения управления, фактически применённого сервером, контрольные состояния и исход. В тестовом контуре сбор включается параметром `ROYAL_AUDIT_COMBAT_REPLAY=1`. Повторный расчёт выполняется тем же движком с шагом 1/60 секунды. Событие управления показывает состояние перед его тактом. Подключение и отключение имеют относительное время, без привязки к такту. До подтверждённого расчёта данные находятся в памяти комнаты. [Захват боя](../../server/audit/replay-pvp-realtime.ts) · [Повторный расчёт](../../server/audit/replay-pvp-realtime-engine.ts)

Формат 3 добавляет закрытую схему событий общего пула. Адаптер флагового тотализатора показывает открытие, принятые билеты, закрытие приёма, итог, распределение и агрегированную проводку каждого аккаунта. Билеты, существовавшие на границе набора, выделены отдельно. Если время принятия билета отсутствует в источнике, пакет содержит только порядок и признак пропуска. [Адаптер пула](../../server/audit/replay-tote.ts)

Для карточного PvP формат 2 хранит начальные публичные позиции, принятые ходы, число карт на руках и в колоде, открытые карты стола и подтверждённый итог. Принятый ход и его время сверяются с исходной квитанцией `pvp_requests`. Если начало или последовательность отметок времени нельзя подтвердить, сохраняется порядок. Движок по этим данным не пересчитывается, так как закрытые карты и порядок колоды отсутствуют. Сбор включается через `ROYAL_AUDIT_CARD_REPLAY=1`. [Карточный адаптер](../../server/audit/replay-pvp-cards.ts) · [Сверка источников](../../server/audit/replay-pvp-cards-storage.ts)

Для платной дуэли со знаками по правилам 4 формат 2 сохраняет фиксацию выбора, раскрытие, счёт и наблюдённые события подключения. До серверного раскрытия реплей показывает только факт выбора. Время принятия сверяется с исходной квитанцией, повтор не заменяет её отметку времени. Просмотрщик сверяет результаты раскрытых раундов. Сбор включается через `ROYAL_AUDIT_TSU_REPLAY=1`. [Адаптер дуэли](../../server/audit/replay-pvp-tsu.ts) · [Сбор состояний](../../server/audit/replay-pvp-tsu-capture.ts)

Формат 4 добавляет профиль `pvp-sport`. В аэрохоккее сохраняются принятые позиции бит, а в бильярде сохраняются удары и установки битка. В обоих режимах пакет содержит точные шаги физики и контрольные состояния. Просмотрщик пересчитывает состояние тем же движком. Если итог банка известен, а игровая причина окончания недоступна наблюдателю, итог игрового реплея помечается пробелом. Сбор включается через `ROYAL_AUDIT_SPORT_REPLAY=1`. [Захват стола](../../server/audit/replay-pvp-sport.ts) · [Проверка физики](../../server/audit/replay-pvp-sport-engine.ts)

Наблюдения новых PvP-адаптеров накапливаются в памяти комнаты до итогового расчёта. Ограниченная очередь записывает пакеты без ожидания со стороны игрового запроса. Пакеты после перезапуска комнаты могут отсутствовать. Финансовые проводки сверяются независимо от доступности пакета.

Служебная команда готовит пакет для сохранённой операции казино или пула в активном тестовом наборе. Укажите новый UUID пакета, затем используйте его в операторской команде `replay`. Для подготовки используется `ROYAL_AUDIT_WORKER_DB_URL_FILE` с правами чтения источников, записи пакетов в схему аудита и пределом временных файлов PostgreSQL до 64 МиБ.

```sh
npm run --silent audit:replay-prepare -- --schema royal_audit --game-schema royal_game \
  --dataset '<test UUID>' --replay '<replay UUID>' --posting '<demo_ledger row id>'
```

Для общего пула вместо `--posting` укажите `--pool '<pool id>'`. Точное повторение сохраняет идентичный пакет. Если после подготовки появилась новая часть истории, подготовьте её под новым UUID. [Права оператора и команды](access.md)

## Просмотр без сети

Соберите локальный HTML в новый файл.

```sh
npm run audit:viewer -- --output ./audit-replay.html
```

Откройте HTML в браузере и выберите подготовленный пакет JSON. Работают пауза, шаг назад и вперёд, перемотка по шкале и переход к номеру события из сигнала. Связанные проводки показываются с исходным ключом и точной суммой, если она есть в пакете. Для шахмат, боя, аэрохоккея и бильярда просмотрщик сверяет состояния совместимым движком. Для дуэли со знаками проверяются раскрытие и счёт. Карточные реплеи показывают подтверждённые публичные позиции. Через известный разрыв состояние не переносится. Код и стили находятся в HTML, а политика страницы блокирует сетевые запросы.

Проверка использует Chromium из Playwright. Для уже установленного совместимого Chrome можно указать абсолютный путь в `ROYAL_AUDIT_VIEWER_BROWSER`.

```sh
node --import tsx --test server-tests/paid-activity-audit-replay-viewer.test.ts
```
