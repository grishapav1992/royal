# Сверка денежных остатков и ответов

CHECK-01, правила R-01 и R-02 из [ТЗ 0.2](https://chatgpt.com/space/page_46dff86b1e548191833f89a998f15ec8). [Реализация](../../server/audit/check-balances.ts) · [Контракт источников](contract.md)

## R-01. Проводки

`reconcileAuditBalance` получает один поток по набору, аккаунту, исходному журналу, активу и компоненту остатка. Доступные, зарезервированные и отложенные единицы сверяются раздельно. Порядок задаёт исходный `sequence`, а не время ответа или сортировка строкой. Пропуски глобальной последовательности между аккаунтами допустимы. Если конкретную ожидаемую строку прочитать не удалось, вызывающий код передаёт явный пробел.

Проверенный начальный остаток берётся из контрольной точки. Сверка прибавляет подписанную сумму каждой проводки и сравнивает расчёт с сохранённым значением. Расхождение не заменяет расчётный остаток сохранённым. Отсутствие сохранённого значения само по себе не прерывает расчёт. Неизвестная сумма или пропущенная строка прерывают расчёт от начала. При неподтверждённом начале или после разрыва доступны только локальные сравнения со значением, сохранённым в соседней строке.

`checkAuditStakeDirection` дополнительно проверяет знак списания по одной платной операции. Вызывающий код объединяет доступную и отложенную части, если источник разделяет дебет. Неизвестная часть даёт статус недостаточности данных. Проверка суммы по правилам игры относится к CHECK-02.

## R-02. Ответ

`checkAuditAttemptBalance` сравнивает сформированный сервером ответ с авторитетным снимком, указанным именно в этой попытке. Ссылки, аккаунт, набор, контур и актив должны совпадать. Транспортные масштабы приводятся к общему масштабу целыми числами без округления. Снимок выбирается по контракту маршрута и должен описывать ту же величину. Например, для ответа провайдера это может быть сумма доступного и отложенного остатков. Текущий остаток после других операций использовать для проверки нельзя.

Законный повтор может указывать на исходный или свежий снимок. Если снимок неизвестен, недоступен или не связан с попыткой, результатом будет пробел покрытия. Сформированный ответ подтверждает наблюдение на сервере. Доставку клиенту эта сверка не проверяет.

## R-03. Повтор и восстановление

`reconcileStoredAuditOperation` читает попытки и подтверждённую команду по аккаунту, маршруту и UUID, а денежные строки по точным ссылкам набора. Для C1 он сверяет полный набор проводок. Ставка и предусмотренная выплата, включая нулевую, считаются раздельно. Два дебета с разными исходными ключами дают расхождение. Для C2 проверяется кратность проводок команды. Полный итог раунда сверяется по R-04. Финансовые движения PvP связаны с банком матча и сверяются по R-05.

Для C1, C2 и PvP наблюдатель сохраняет версионированный отпечаток формата, по которому соответствующий сервер проверяет повтор. Тело запроса и содержимое исходного ключа остаются вне записей аудита. Отсутствующий отпечаток даёт пробел. Если изменённая команда получила отказ, отказ виден отдельно от результата денежной сверки. Если изменённая команда потеряла ответ, решение остаётся неизвестным. Внешние платёжные команды и другие форматы используют свои проверки источников.

`reconcileStoredAuditAttempt` связывает эту сверку с сохранёнными проводками. Для известных денежных маршрутов виртуального кошелька и ответа WS `pvp` он читает точный ключ `demo_ledger` из набора попытки и берёт сохранённый `availableAfterUnits`. Ссылка на собственное наблюдение ответа или на другой журнал отклоняется. Если последнее движение кошелька было пополнением или другой операцией, его сохранённый остаток допустим при точной ссылке. Отсутствие ключа в наборе, недоступность источника и неподдерживаемая запись сохраняют разные причины пробела. Для платёжного USDT и иных видов остатка нужна отдельная подтверждённая связь с источником.

```sh
node --import tsx --test server-tests/paid-activity-audit-check-balances.test.ts
node --import tsx scripts/database-test.ts --import tsx --test server-tests/paid-activity-audit-check-repeats.test.ts
```
