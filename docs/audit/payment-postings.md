# Денежные источники вне обычного расчёта раунда

DATA-05 дополняет [контракт](contract.md) и [матрицу покрытия](coverage.md). [Адаптер](../../server/audit/payments.ts) читает подтверждённые исходные строки по ID в отдельной транзакции PostgreSQL только на чтение. Он не вызывает обработчики кошелька, оплаты или провайдера.

| Источник | Проводка и связь |
| --- | --- |
| Платёжный `crypto_ledger` | `entry_key` задаёт пополнение, резерв вывода, завершение вывода, возврат или корректировку. Суммы доступного и зарезервированного остатка сохраняются отдельно, в USDT с масштабом 6. Ссылка ведёт в `crypto_operations` или `finance_adjustments`. |
| NOWPayments Sandbox | Каждая фактическая часть зачисления имеет отдельный `demo_ledger.id`. Части связаны с одним ID заказа. Отложенное зачисление без проводки в финансовый отчёт не попадает. |
| Историческое прямое пополнение | Запись виртуального депозита сопоставляется с `demo_operations(account_id, operation_id)`, если такой запрос сохранился. |
| Покупка образа и наградной спин | Для покупки `bet` означает списание цены, `refund` означает возврат. Подтверждение покупки не создаёт второго списания. Наградное `win` означает выплату из награды, без денежной ставки. Связи используют `skin_purchases.id` и `progression_spin_uses(account_id, operation_id)`. |
| Casino Api Pro Sandbox | `demo_ledger` хранит доступную часть, `capro_pending_ledger` хранит отложенную. Внутренний перенос связан по аккаунту и ID операции. Обе стороны имеют вид `release`, а сумма переноса между остатками равна нулю. Отложенный остаток передаётся отдельно от резерва. |

Операции общего кошелька имеют актив `VIRTUAL_USD` с масштабом 2. Среда Sandbox провайдера и среда набора аудита не определяют валюту общей проводки. Адаптер возвращает поля контракта отдельно от связей и расширенных сведений. При отсутствии подтверждающей операции сохраняются исходная сумма и пометка `partial`. Неизвестный остаток передаётся как `null`. Для неподдерживаемого вида проводки функция возвращает `null`, и вызывающий код должен показать непокрытый исходный ключ.

Платёжный outbox и `payment_credit_events` содержат сведения о доставке канонического платёжного события. Связь идёт по SHA-256 ключа проводки, который платёжный сервис использует для `event_id`. Задержка доставки не меняет дату первичной проводки. Отражение события в игровом сервисе не увеличивает сумму операций игрока. [Outbox](../../server/payments/outbox.ts) · [Игровая проекция](../../server/payments/credits.ts)

Пробелы остаются для будущих задач. Старый `game:<id>` платёжного журнала представляет итоговую нетто-сумму и не раскладывается этим адаптером на выдуманные ставку и выигрыш. Номинал Telegram Stars в XTR относится к заказу, а проводка относится к зачислению USDT. Возврат Stars после зачисления может создать только отметку проверки и блокировку вывода, без обратной проводки. История отклонённых запросов и результаты отправки ответов HTTP или WS отсутствуют в этих источниках. Адаптер также не выводит исходные тела уведомлений и платёжные реквизиты.

Проверка на одноразовой PostgreSQL:

```sh
node --import tsx scripts/database-test.ts --import tsx --test server-tests/paid-activity-audit-payments.test.ts
```
