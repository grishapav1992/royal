# Доступ к аудиту платной активности

У оператора свой PostgreSQL LOGIN. Администратор создаёт отдельную группу NOLOGIN и выдаёт операторам членство в ней. Имя группы передаётся в установщик доступа. Используйте учётные записи без владения объектами, привилегированных атрибутов, других членств и прямых прав на таблицы. Задавайте пароли через действующий механизм управления секретами. При отзыве доступа удалите разрешения оператора из таблицы ACL и членство в группе. Перед повторным использованием имени проверьте, что старых разрешений для него нет.

```sql
CREATE ROLE royal_audit_reader NOLOGIN;
GRANT royal_audit_reader TO named_operator;
```

Установщик выдаёт группе USAGE на схему аудита и EXECUTE на ограниченные функции. Миграция привязана к выбранному имени группы. Роли установки, управления разрешениями и очистки обслуживаются отдельно от операторов отчётности.

Администратор добавляет разрешения в `audit_report_acl` отдельно для каждой пары `dataset_id` и `source_namespace`. Запись ссылается на зарегистрированный источник набора. Функции используют PostgreSQL `SESSION_USER` как имя оператора. Переход через `SET ROLE` сохраняет эту идентичность.

```sql
INSERT INTO royal_audit.audit_report_acl(operator_name,dataset_id,source_namespace)
VALUES ('named_operator', '<dataset UUID>', 'royal_game.demo_ledger');
ALTER ROLE named_operator SET temp_file_limit = '64MB';
```

После миграций источников и схемы аудита установщик запускает функции `installAuditReportAccess(db, group)` и `installAuditPlayerReport(db, group, sources)`. В `sources` указываются фактические имена игровой схемы и, если подключён платёжный источник, его схемы в той же базе. Оператору выдаётся EXECUTE на функции, а установка выполняется отдельной учётной записью. ## Журнал выгрузок

- `audit_report_begin(dataset, 'player', filters)` фиксирует оператора, набор, тип, фильтры и время начала. Обязательные фильтры включают `accountId`, `fromMs`, `toMs`. Можно указать `category`, `gameId`, `modeId`, `asset`, `contour`. Период ограничен 31 сутками.
- На одного оператора разрешена одна активная выгрузка. Через пять минут её идентификатор теряет силу. Следующий разрешённый запуск этого оператора отмечает просроченную запись как `expired`.
- `audit_report_finish(job, outcome, row_count, byte_count, reason)` фиксирует результат своей активной выгрузки. Успех требует указать количество строк и байтов. Для ошибки и отмены принимаются фиксированные коды причин. Запись результата и счётчиков отражает сообщение клиента выгрузки.
- Запуск и завершение выполняются отдельными короткими транзакциями. Чтение отчёта использует отдельную транзакцию. Запись о начале сохраняется при ошибке или отмене чтения.

Страницы доступны после коммита задания. Каждая страница заново проверяет права оператора и срок задания. В активном наборе чтение идёт по мере коммитов. Поздно завершившаяся операция с ключом до уже прочитанной страницы может войти только в следующую выгрузку. Для фиксированного состава проводок используйте закрытый набор.

## История игрока

Перед запуском задайте `ROYAL_AUDIT_DB_URL_FILE` как путь к файлу с PostgreSQL URL оператора. Для подключения по TLS задайте `ROYAL_AUDIT_PGSSLMODE=verify-full` и при необходимости `ROYAL_AUDIT_PGSSLROOTCERT`. Команда использует явное операторское подключение. В примере период задан в UTC.

```sh
npm run audit -- player --schema royal_audit --dataset '<dataset UUID>' --account '<account ID>' \
  --from 2026-11-07T00:00:00Z --to 2026-11-08T00:00:00Z --output ./postings.csv
```

Нижняя граница периода включена, верхняя исключена. Дополнительные фильтры задаются через `--category`, `--game`, `--mode`, `--asset`, `--contour`. В консоль выводятся ID задания и объём файла. CSV сохраняет исходный порядок по времени, источнику и числовому ID строки, точные целые денежные единицы и один ряд на проводку. Комиссии без отдельной проводки раскрываются в проверке банка. Ожидаемый баланс вычисляется от контрольной точки для первой проводки или от сохранённого остатка соседней проводки. Колонка `expected_balance_basis` различает эти случаи и отсутствие данных. CSV показывает финансовую проекцию, а проверка правил и доказательств остаётся отдельной операцией.

Лимиты пилота составляют 31 день, 10 000 строк, 20 000 просмотренных ссылок, 16 МиБ CSV, 60 секунд на чтение и запись и 5 секунд на запрос. Роль должна иметь ограничение временных файлов PostgreSQL не выше 64 МиБ. Существующий путь сохраняется, временный файл создаётся с правами владельца в той же папке, финальное имя появляется после полного завершения записи. Отмена закрывает соединение чтения и удаляет временный файл. Если файловая система после публикации не дала удалить временное имя, команда сообщает его в `cleanupPending`. При потере связи с журналом после публикации команда сообщает `journal-unavailable` с ID задания. Самостоятельное чтение через SQL использует ограниченную функцию с активным заданием. Показатели завершения передаёт клиент.

Строки с потенциальными формулами экранируются при создании файла. Для точного отображения длинных чисел импортируйте денежные колонки в таблицу как текст. Пробелы покрытия, в том числе отсутствие исходной строки, отражаются отдельным статусом. Массовая выгрузка всех игроков требует отдельного нагрузочного допуска.
