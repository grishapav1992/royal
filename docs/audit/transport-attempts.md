# Запись попыток и сформированных ответов

DATA-06. Аудит присваивает каждой наблюдаемой попытке собственный ID и сохраняет ID операции отдельно. Записываются только поля [общего контракта](contract.md). HTTP фиксирует баланс из сформированного JSON. Если маршрут отдаёт общий виртуальный кошелёк, наблюдатель привязывает ответ к последней строке журнала в серверном снимке до сериализации. R-02 читает эту строку из выбранного набора. Значение, увиденное в ответе, и контрольное значение извлекаются независимо. [Сверка остатков и ответов](check-balances.md)

| Источник | Что наблюдается | Предел связи |
| --- | --- | --- |
| HTTP общего кошелька и наград | Запросы изменения, баланс ответа, код HTTP, завершение отправки или закрытие соединения. | Для C1 и других маршрутов без признака повтора успешное решение остаётся `unknown`. Сравнение доступно при точном ключе проводки в текущем наборе. |
| HTTP платежей и покупок | Выбранные маршруты клиента с подтверждённым аккаунтом и безопасным шаблоном пути. | Платёжный баланс можно сохранить без независимой связи для R-02. Callback без подтверждённого локального аккаунта остаётся за пределами наблюдения попыток. Денежные проводки читаются по своим источникам. |
| WebSocket PvP | Отдельные команды и прямые ответы для исходного соединения, сессии и ID запроса. Рассылки обновлений комнаты пропускаются. | Действующий протокол PvP не отмечает ветку успешного повтора, поэтому одинаковые UUID видны как разные попытки с решением `unknown`. |
| WebSocket платных действий комнаты | Выбранные действия в текущем платном контексте. | У действий без прямого подтверждения ответ `not-observed`. Высокочастотное управление относится к потоку воспроизведения. |

Наблюдатель включается для заранее созданного активного набора. Передайте игровому процессу серверную схему через `ROYAL_AUDIT_SCHEMA` и один точный UUID через `ROYAL_AUDIT_TEST_DATASET_ID` для `environment=test` или `ROYAL_AUDIT_LIVE_DATASET_ID` для `environment=live`. Миграции выполняются при подготовке набора. Приложение использует отдельный пул с одним соединением. Запись выполняется асинхронно и не входит в транзакцию кошелька. При остановке сервера очередь осушается. Оператор останавливает наблюдение до закрытия набора. [Переключение](cleanup.md)

Очередь ограничена 128 ожидающими записями на процесс. Переполнение и ошибки записи отражаются счётчиком `audit_attempt_capture_gaps` и диагностикой без содержимого запроса. После восстановления доступа сохраняется диапазон времени и суммарное число известных пропусков процесса. При аварийном завершении незаписанные наблюдения в памяти могут потеряться. Финансовый журнал и транзакционные ссылки на проводки остаются отдельным источником.

На одноразовой PostgreSQL проверяются обрыв после коммита, повтор с одним набором проводок, отказ при изменённой сумме и ответ с балансом −1. Для PvP проверяются живое WebSocket-соединение, ответ на повтор и отказ при изменении запроса. Отдельные тесты проверяют корреляцию при параллельных командах, разрыв связи и отказ наблюдателя.
