# Проверка перебалансировки Неополиса и Драконы

Исправление согласовано с актуальными изменениями `origin/main` до `6b08e5b`: общий тестовый USDT, PvP, новые коллекции, ателье, финансовый кабинет и перестановка левой части зала сохранены. Неополис остаётся неопубликованным прототипом. Рабочий сервер этой задачей не обновлялся.

Математические параметры, выборки, интервалы и границы обязательного контроля описаны в [квалификации](qualification.md). Обе игры успешно прошли полную квалификацию; проверены 7 669 287 оплаченных раундов Неополиса и 5 000 000 Драконы, включая все бесплатные продолжения. Повтор после приведения хешей к одинаковому формату Windows/Linux дал те же результаты.

## Подтверждённые проверки

| Проверка | Результат |
| --- | --- |
| `npm run check:rtp` | Оба отчёта соответствуют текущим математическим исходникам, политикам и версиям модулей |
| `npm run test:rtp-gate` | 9 тестов, включая отказ для прежнего избыточного RTP, изменения исходников, отсутствующих ставок и новых игр без квалификации |
| `npm run test:slot-balance` | 43 теста прошли после согласования с последним main |
| `npm run check:finance` | Типы финансового сервиса и его тестов проверены |
| `npm run build` | Проверка RTP, TypeScript, 116 независимых модулей, клиент и сервер собраны |
| `server-tests/independent-modules.test.ts` | 7 тестов, контракты, контроль содержимого пакетов и границы общего host прошли |
| `playwright.neopolis.config.ts` | Все 10 сценариев прошли, два сценария дополнительно перезапущены после исправления тестового выбора игры и при меньшей нагрузке |

Серверные проверки охватывают честное воспроизведение истории, старые версии правил, сохранённые бонусы, перенос сборки команды, защиту от старых клиентов, целые денежные единицы, ставки, максимальную ответственность, параллельные повторы UUID и однократный итог серии. Отдельный HTTP-сценарий проходит через актуальный `/api/game-wallet`, приватный финансовый сокет и настоящий журнал Nile, проверяет правила 3 Драконы и отсутствие второго начисления. Аудитор журнала подтверждает сохранение денег. Искусственные балансы и аккаунты находятся только во временной PostgreSQL; рабочие данные не используются.

В браузере проверены русский и английский Неополис, телефоны и десктоп, вращения, каскады, подтверждённые суммы, потерянный ответ, закрытие и восстановление, все три босса и смены арен, музыка, mute и пауза. Дракона проходит полную бонусную серию с дробными выплатами, перезагрузкой и одной ставкой. Её окно в настоящем host открывается через актуальную коллекцию, чат остаётся подключённым на 1440 × 1000 и 390 × 844. Снимки просмотрены. Проверка звукового синхронизатора сохранила прежний инженерный допуск 65 мс; измерение под нагрузкой один раз дало около 70 мс, отдельный повтор прошёл. Звук и анимации этим исправлением не перенастраивались.

Для редких кампаний браузерный стенд подаёт воспроизводимую случайность через настоящий транзакционный `DemoExpansionStore`. Фикстура существует только в локальном Vite-стенде, включается для теста и не импортируется рабочим сервером. Обычный запуск стенда использует случайность рабочего движка и одноразовые демомонеты, отдельно от журнала USDT.

## Ограничения общего набора тестов

Это не заявление о прохождении всего `test:auth`. Дополнительный запуск старого `card-math-versions.test.ts` дал четыре ошибки: устаревшие сценарии начинают уже удалённые карточные игры, а отдельному сценарию нужен собранный Go-движок. Ограничение удалённых игр воспроизведено и с прежним `origin/main:server/demoExpansion.ts`. После перехода main на общий USDT неизменённый `wallet-account.test.ts` также не стартует в Node из-за `location is not defined` при статическом импорте браузерного `NilePlayClient`. Эти архивные тестовые фикстуры не менялись в данной задаче. Прикладные HTTP-проверки владельца и версии запроса для исправленных игр находятся в отдельном проходящем наборе.

GitHub workflow быстрого контроля и отдельного полного пересчёта добавлены. Состояние запущенных GitHub Actions необходимо отличать от локальных результатов выше. Защита ветки в настройках репозитория этим изменением не настраивается.
