# Затопленный храм: математика и сервер, этап 2

Дата: 26 октября 2026 года. Игра `studio-flooded-temple`, правила 1, прогресс 1, host API 1. Этап 2 реализует вычисления и серверные сессии. Игровой интерфейс, выбранный арт, анимации и звук относятся к следующим этапам. Production не изменялся.

## Результат

Независимый полный перебор даёт точный RTP **96% при оптимальном маршруте**. Для любой допустимой стратегии ожидаемый возврат находится между 90% и 96%. Это ожидания по полным оплаченным раундам, а не обещание возврата отдельной сессии.

| Стратегия бонуса | Точный RTP, округлённый для показа |
| --- | ---: |
| Оптимальная сумма за оставшиеся шаги | 96% |
| Сначала самый дорогой достижимый сундук | 95,34065934% |
| Сначала ближайший сундук | 94,37362637% |
| Равномерный случайный допустимый переход | 90,66093262% |
| Немедленно закончить бонус | 90% |

Числа одинаковы на всех шести разрешённых ставках: 10, 20, 50, 100, 200 и 500 отображаемых единиц. В общем игровом транспорте это строки `1000`, `2000`, `5000`, `10000`, `20000`, `50000` при масштабе 100. Реальную валюту и баланс определяет host; отдельного кошелька у игры нет.

## Замороженный генератор

Параметры находятся в [floodedTempleData.json](../../src/shared/floodedTempleData.json). Спин выбирает планировку, смещение рисунка наград, уровень наград и положение реликвии. Карта полностью определяет результат исследования; выбор игрока не вызывает подмену карты или наград.

- Восемь базовых планировок, четыре смещения рисунка сундуков, четыре уровня наград и два положения реликвии дают **256 базовых карт**.
- Планировки и смещения выбираются равномерно. Положение реликвии имеет веса 98 и 2. В редком варианте реликвия достижима через настоящий проход; в обычном остаётся в изолированной комнате.
- На доступных для содержимого клетках повторяется рисунок коэффициентов 0,05 / 0,10 / 0,20 / 0,50 ставки со смещением 0-3. Вход, рычаг и реликвия исключены из заполнения. Уровень 0 оставляет такие клетки пустыми.
- Содержимое соседних комнат связано выбранным рисунком и планировкой. Модель не утверждает, что двадцать комнат являются двадцатью независимыми барабанами.

| Масштаб рисунка наград | Целый вес из 612 000 |
| --- | ---: |
| 0 | 367 200 |
| 1 | 220 535 |
| 5 | 23 653 |
| 100 | 612 |

В экспедиции восемь отдельных планировок и два масштаба наград дают **16 бонусных карт**. Масштабы 1/2 и 3/2 имеют веса 113 и 69 из 182; планировки равновероятны. На каждой карте шесть переходов, одна верёвка, один рычаг с указанной решёткой, видимые сундуки и провал. Реликвий и повторных бонусов в экспедиции нет.

Случайность используется только при принятии начального спина через серверный `crypto.randomInt` с целыми границами. Бонусные решения не используют новые случайные числа. Недопустимая граница или результат источника случайности отклоняются.

## Полный оплаченный раунд

Один раунд включает одну ставку, всё базовое исследование, открытые рычагами проходы и весь бонус. Сундуки оплачиваются только при первом посещении. Результат сохраняется до одного окончательного начисления, поэтому промежуточная сумма не является отдельным пополнением кошелька.

Каждый сундук считается как `floor(stakeUnits * coefficientHundredths / 100)` в целых числах. Все разрешённые ставки кратны 100, а коэффициенты целые, поэтому на этом профиле нет потерь от округления. Проверены все ставки, а не только ставка 100.

Точные вклады:

`E[base] / stake = 9/10`.

`P[expedition] = 1/50`.

`E[bonus | expedition, optimal] / stake = 3`.

`RTP(optimal) = 9/10 + 1/50 * 3 = 24/25`.

Основная выплата не отнимается при неудачном выборе маршрута. Каждая бонусная награда неотрицательна, а досрочное завершение разрешено. Это даёт нижнюю границу 9/10 для любой стратегии. Динамическое программирование выбирает максимальную выплату среди всех продолжений каждой видимой карты; его ожидание 24/25 даёт верхнюю границу для любой адаптивной или случайной стратегии.

## Распределение результата

Полный перебор 2176 сочетаний базовой и, где доступна, бонусной карты построил распределение полной выплаты для оптимальной стратегии. Веса сочетаний учитываются, они не равновероятны.

| Показатель | Значение |
| --- | ---: |
| Ненулевая полная выплата | 41,2% |
| Выплата больше принятой ставки | около 33,47496885% |
| Частичный возврат меньше ставки | около 7,72503115% |
| Выплата ровно в размере ставки | 0% |
| Вход в бонус | 2% |
| Достижимый максимум полной выплаты | 230 ставок |
| Вероятность этого максимума | 49 / 1 600 000, или 0,0030625% |
| Стандартное отклонение полной выплаты | около 4,8656945961 ставки |

В доказательстве сохранены точные рациональные моменты. Дисперсия составляет `3516019209259 / 148512000000` в квадратах ставки; корень показан округлённо. Эти величины описывают распределение выплат. Они не являются оценкой удовольствия или универсальной категорией «высокой» волатильности.

Технический потолок расчёта и резерва составляет 500 ставок. Независимая проверка ограничивает даже раздельно взятые максимумы базы и бонуса величиной 235,55 ставки; действительный максимум полного достижимого сочетания равен 230. Поэтому потолок не обрезает выплаты этого профиля. Число 500 нельзя показывать как достижимый приз. Резерв общего сервера использует этот консервативный технический предел.

## Независимость расчёта и серверная сверка

[Независимая модель](../../scripts/game-math/rtp-temple-model.mjs) читает записи параметров, но не импортирует производственный расчёт связности, начислений или ходов. Связность вычисляется отдельным алгоритмом замыкания, решения бонуса отдельным обходом состояний и рациональной арифметикой.

Проверены **1032 различных состояния бонуса** и **1814 переходов**, включая добровольное завершение. Состояния учитывают комнату, оставшиеся шаги, посещённые клетки, рычаг и мост. Разные истории, ведущие к одному такому состоянию, имеют одинаковые будущие возможности и начисления. Вход пустой, возврат через сундук не даёт повторной награды, шестой переход сначала собирает содержимое и затем завершает бонус.

[Программа квалификации](../../scripts/game-math/rtp-temple.mjs) вызывает настоящие серверные `startTemple` и `moveTemple`, проверяет целые суммы, состояния и завершение всего раунда. Для каждой ставки выполняется 3102 детерминированных сопоставления: каждая базовая карта, каждое бонусное состояние и каждый допустимый переход. Два независимых seed, `2026102601` и `2026102607`, добавляют по 64 полных раунда на каждое сочетание ставки и стратегии. Всего **22 452 серверных сопоставления**.

Seed используются для дополнительной проверки взвешенного выбора и воспроизведения, а не для оценки самого RTP. Аналитическое ожидание получено полным перебором, поэтому статистический доверительный интервал здесь не применяется. Результаты не выдаются за измеренную отдачу production.

Доказательство [flooded-temple-v1.json](qualifications/flooded-temple-v1.json) сгенерировано штатной командой. Оно содержит точные дроби, результаты всех 30 сочетаний ставок и стратегий, покрытие, digest каждой серверной сверки, policy SHA-256 и хеши актуальных исходников. Файл не редактируется вручную.

Быстрый gate заново вычисляет независимую модель, покрытие и ожидаемые digest серверных траекторий, затем сравнивает архивное доказательство. Он не запускает сам производственный движок. Полная команда квалификации действительно исполняет его и сравнивает полученные результаты. Правки к расчёту, диспетчеру и указанным финансовым маршрутам делают доказательство устаревшим. Нельзя убирать исходники, стратегии, ставки или независимые seed для обхода проверки. Legacy baseline и прежние доказательства других игр сохранены.

## Сервер, совместимость и деньги

- Реализация [server/games/floodedTemple.ts](../../server/games/floodedTemple.ts) подключена к существующему `DemoExpansionStore`, общим `demo_casino_sessions` и `demo_casino_requests`. Новых балансов, таблиц денег или сервисов нет.
- Сессия фиксирует правила 1 и исходную ставку внутри самого состояния, выбранные карты, историю решений, шаги, верёвку, открытые решётки и накопленную сумму. Сохранённое представление заново вычисляется по принятой истории; произвольная сумма из снимка не считается основанием для выплаты.
- Принятый UUID не исполняется второй раз. Новое действие требует актуальной ревизии; параллельный устаревший ход отклоняется. Чужой аккаунт не может продолжить сессию.
- Незавершённый бонус восстанавливается после создания нового store или runtime. Закрытие окна само по себе не завершает раунд. Новая ставка в той же игре запрещена до окончания похода.
- Оплата проходит через существующий общий журнал USDT · Nile и его транзакцию. Резерв и доступный баланс остаются ответственностью общего финансового контура. Ошибка записи журнала откатывает ход, сумму, резерв и receipt вместе.
- Старые клиенты не видят сессии храма и не могут начать игру. Нужен `X-Royal-Temple-Rules: 1`. Общий HTTP-прокси передаёт необязательное поле `templeRules` приватному runtime; старые команды без него остаются совместимыми.
- Первый выпуск данных является правилами 1. При будущем изменении математики сохранить эту версию для принятых сессий и добавить новую версию расчёта. Не переписывать принятую карту, ставку или таблицу по условиям следующего раунда.

Независимый пакет `games/flooded-temple/` содержит контракт и минимальный каркас без команды ставки. Он зарегистрирован для сборки и проверки совместимости, но не добавлен в активный каталог Royal. Игровое поле и управление появятся на этапе 3. Для выпуска нового клиента сначала нужен совместимый общий host/backend; отдельно публиковать каркас нельзя.

## Проверки и воспроизведение

```text
npm run qualify:rtp -- --game studio-flooded-temple --write-proof
npm run check:rtp
npm run test:rtp-gate
npm run test:temple
node node_modules/typescript/bin/tsc --noEmit
npm --prefix games/flooded-temple run build
```

В тестах проверяются точность всех ставок, обычный раунд без бонуса, все типы переходов, явная верёвка, последний шаг, циклы и повторные сундуки, раннее завершение, подмена снимка и ставки, неверная случайность, UUID, ревизии, параллельные запросы и откат начисления. Полный HTTP-сценарий использует установленный общий маршрут, настоящий приватный финансовый socket и изолированный тестовый журнал. Производственные аккаунты, данные и RPC сети не используются.

В CI добавлены полный пересчёт этого профиля и запуск `test:temple`. Прохождение локальных проверок не утверждает, что ещё не запущенный удалённый CI уже завершился.
