# Проверка безопасности новых игр Рояля

8 октября 2026 года, локальная версия проекта. Проверены Royal Fruits с EZSlotsJS и Royal Dice, Mines, Plinko, Limbo, Keno на основе vFair, их серверные операции, общий демокошелёк и зависимости.

В проверенных исходниках не обнаружено скрытой отправки данных, выполнения сторонних команд или чтения секретов. После исправлений реальный браузерный сценарий входа в зал и игры на всех шести автоматах завершился без попыток обращения к внешним адресам. Найденные проблемы приватности, нагрузки и запуска исправлены локально. Во время первоначального аудита production-сервер не изменялся. Последующая публикация описана ниже.

## Исправленные проблемы

| Проблема | Возможное последствие | Исправление |
| --- | --- | --- |
| Автоматическая загрузка прежнего каталога Luelon без его автомата в зале | Внешний сервис видел сетевое обращение браузера и его IP. Запрос уже использовал `credentials: omit` и `no-referrer`, не передавал пароль или баланс | Превью и предварительная загрузка включаются только при наличии соответствующего автомата |
| Прежний результат оставался после смены аккаунта, в том числе при завершающейся анимации | Следующий пользователь общего браузера мог увидеть результат предыдущего игрока | Полный сброс результата, подсветки и сообщений; отмена таймеров и анимаций; ответы проверяются по смене аккаунта |
| GET, повторы и отклонённые запросы обходили лимит новых успешных операций | Авторизованный клиент мог многократно нагружать кошелёк | Общий лимит 240 запросов за окно 60 секунд на аккаунт до разбора тела и операций кошелька. Хранилище ограничено 10 000 аккаунтов, записи истекают |
| Подсчёт последних действий Mines просматривал историю аккаунта без подходящего индекса | Стоимость каждого нового хода росла вместе с историей под транзакционной блокировкой | Индекс `(account_id, created_at)`; тест проверяет план запроса и сохранение лимита действий |
| Limbo импортировал hash-модуль с зависимостью только для разработки | Сборка могла не запуститься после `npm ci --omit=dev` | Сервер использует чистый адаптер 32-битного исхода с идентичной арифметикой. Математика и сохранённые правила не изменены |
| Прежняя зависимость инструмента локального запуска `shell-quote 1.9.0` | Выполнение команды при специально сформированных недоверенных аргументах командной строки | Точечное закрепление версии `1.11.0` для `concurrently`, остальные версии пакетов сохранены |

Уязвимость `shell-quote` описана в [сообщении сопровождающего GHSA-pqg4-j6r4-53mv](https://github.com/ljharb/shell-quote/security/advisories/GHSA-pqg4-j6r4-53mv): затронуты версии `>=1.8.4, <1.11.0`, исправление выпущено в 1.11.0. Для эксплуатации требуется недоверенная строка с переводом строки после токена комментария. В Royal команды локального запуска фиксированы; пути эксплуатации из игрового HTTP API не обнаружено. Зависимость существовала до добавления этих игр.

Дополнительно усилен ввод: авторизация выполняется перед JSON-парсером, тело ограничено 2 КБ, сжатые запросы отклоняются до распаковки, ошибки возвращаются как короткий JSON без исходного тела и стека сервера. Символы барабанов выводятся через `textContent`, включая строки, похожие на HTML или адрес картинки. В прежнем Royal использовались фиксированные эмодзи; подтверждённого XSS через символы не было.

## Передача и хранение данных

Игровые клиенты используют собственные `/api/demo-wallet/operations` и `/api/demo-wallet/mines`. В перенесённых математических модулях и отображении нет скрытых `fetch`, telemetry, `eval`, запуска процессов или доступа к файлам секретов. Адрес SVG namespace и ссылки в комментариях не выполняют сетевые запросы. Внешняя загрузка Google Fonts из upstream EZSlotsJS была удалена при первоначальной адаптации.

Незавершённые запросы хранятся в `sessionStorage` отдельно для каждого аккаунта. Пароль, авторизационная cookie и скрытая раскладка Mines туда не записываются. Cookie авторизации имеет HttpOnly; в production также Secure. В активной Mines API возвращает только публичное состояние без `mineCells`, `mine_cells`, резервов и seed. Раскладка завершённой партии доступна её владельцу.

Идентификатор аккаунта в заголовке связывает запрос с аккаунтом вкладки; владельца определяет серверная cookie. Чужая cookie, отсутствующий заголовок и несовпадение владельца возвращают 401. Неподходящий Origin и cross-site запрос возвращают 403. SQL использует параметры. Клиент не задаёт выигрыш, мины или результат броска. Повторы и начисления проводятся атомарно и разделены по аккаунтам. Новые игры не расширяют разрешённые игры USDT и Nile.

## Результаты проверок

- 29 серверных проверок в выбранном наборе прошли: авторизация, чужие партии, Origin, подмена исхода и выплаты, SQL и prototype-входы, размер тела, параллельные повторы, лимиты, откаты, резерв Mines и прежний кошелёк Nile. Усиленный JSON-парсер дополнительно проверен после последней правки.
- 14 браузерных проверок прошли на изолированных API-фикстурах: смена аккаунта во время анимации и после результата, запоздавший ответ, восстановление незавершённого запроса, очистка Mines и инертный HTML.
- Три прежних сценария EZSlotsJS прошли после изменений: обычное вращение, потерянный ответ и конфликт с другой незавершённой игрой.
- Один сценарий всех шести автоматов прошёл через настоящий локальный сервер: 0 внешних обращений, авторизационная cookie недоступна JavaScript, пароль и скрытая игровая информация отсутствуют в браузерных хранилищах.
- Сборка и проверка финансовых типов прошли. Отдельная временная копия с одними production-зависимостями запустила сервер и провела ставки Limbo и Mines. Она не содержала `.env`, базы проекта или ключей.

## Границы вывода

Это локальный аудит указанной линейки, не проверка всего production-окружения или независимая сертификация. Первоначальная проверка запуска выполнена на Node v25.8.1 с production-зависимостями. При последующей публикации также собран и проверен настоящий Docker образ Node v22.23.3, см. подтверждение публикации ниже. Нативные бинарники всех зависимостей не исследовались полностью. Нулевой результат npm означает отсутствие известных записей в его базе на момент проверки.

Лимит HTTP действует в пределах одного процесса. При масштабировании на несколько процессов потребуется общий лимит. Журналы операций сохраняются для надёжного повтора, поэтому объём базы требует обычного контроля. Внешние провайдеры казино, инфраструктура и отдельный финансовый сервис не входят в утверждение об отсутствии внешних обращений шести собственных игр.
