# Финансовый кабинет

Страница `/admin` работает отдельно от игрового клиента. Язык русский, даты отображаются по Москве. Доступ разрешён только существующим аккаунтам из `FINANCE_ADMIN_ACCOUNT_IDS`, перечисленным через запятую. Пустая настройка закрывает кабинет. Почта используется только при первоначальном поиске владельца; постоянное разрешение закрепляется за UUID, а не за именем или первым посетителем. Для MVP используется один владелец. Пароль и сессия общие с казино; каждое денежное действие дополнительно требует пароль владельца.

## Источники и отчёты

NOWPayments и прямой USDT относятся к реальным средствам, Nile к тестовым. Каждый контур выбирается отдельно. История доступна и при отключённом приёме платежей. Недоступный остаток провайдера отображается как неподтверждённый, а не как ноль. Остатки относятся ко всему контуру сейчас; фильтры применяются к истории, итогам, игрокам, играм и диаграмме.

Доступны период, игрок по имени/почте/UUID, игра, противник казино/PvP, вид операции, статус и диапазон суммы. Период включает начальную и конечную календарную дату Москвы; API использует полуоткрытый интервал миллисекунд. Отбор относится ко времени создания денежной операции. У исторических поступлений Nile дата отсутствует в запечатанном журнале: они доступны за всё время и исключаются при отборе по датам. Интерфейс показывает предупреждение о таких записях.

Суммы хранятся и передаются целыми микро-USDT. Отчёты используют PostgreSQL NUMERIC, клиент форматирует BigInt. Вычисления остатков не используют числа с плавающей точкой. Зачисленные пополнения берутся из фактической суммы зачисления; запрошенная сумма платежа может отличаться. Незавершённый вывод не считается завершённым денежным оттоком. Результат казино включает денежный результат завершённых игр против казино и комиссию завершённых PvP. Расходы бизнеса не учитываются. Покупки ателье идут отдельным видом операций.

Nile включает:

- Зачисление игроку и пополнение резерва отдельными строками, даже если их финансировал один внешний перевод. Резерв не увеличивает сумму депозитов игрока.
- Старые раунды Royal Coins из основного журнала.
- Все новые игры общего кошелька из проекции игровых движков в той же финансовой схеме. Внутренние таблицы исторически называются `demo_*`, но в схеме Nile их изменения выполняются внутри транзакции финансового журнала и отражают только USDT. Отдельная историческая демосхема игры не читается и её балансы не импортируются.
- Оплаченные действия внутри продолжительных партий. Общий ID партии связывает ставки и выплаты; количество партий считается по уникальному ID, журнал сохраняет отдельные денежные действия.
- Оба участника каждого PvP: ставка, резерв, противник, результат и выплата. Комиссия берётся из проводки казино и распределяется поровну между участниками для персональных отчётов. Например, при 50 + 50 победителю поступает 95, казино 5, персональная доля комиссии каждого участника составляет 2,5. В сводке комиссия не дублируется. Отмены возвращают ставки и не создают игровой выручки.
- Резервирование, оплату и возврат покупки ателье.

Карточка игрока показывает текущий доступный и зарезервированный баланс выбранного контура, историю и итоги по выбранным фильтрам. Из карточки можно перейти ко всему журналу игрока. CSV выгружает текущую страницу, а не скрытую часть истории. Поля экранируются для CSV и от формул электронных таблиц.

## Управление

Корректировка перемещает средства между доступным балансом игрока и свободным резервом казино. Она не создаёт депозит или блокчейн-перевод. Недостаток свободного резерва и списание сверх доступных средств отклоняются. Для NOWPayments остаётся единый платёжный журнал с доставкой изменения игровому сервису через подписанный outbox. Для Nile и прямого USDT добавляется запечатанное событие `adjustment`, проверяемое полным аудитом. Старые события не изменяются.

Приостановка игрока закрывает создание платежей, выводов, новых казино-партий, новых/принимаемых PvP и новых покупок ателье через общий host. Завершение уже принятых операций, игровых партий, возвраты и уведомления провайдера продолжаются. Приостановка не отменяет запросы, уже находящиеся в обработке. Это ограничение новых денежных действий, а не удаление аккаунта или сессии.

Проверка NOWPayments сверяет и продолжает обработку ранее подтверждённой операции, включая ожидающий вывод. Это явно указано в подтверждении. Автоматический выпуск не выполняет начислений, выводов или ставок на боевых аккаунтах.

У каждого действия UUID, автор и обязательная причина. Повтор того же действия безопасен; повтор с изменёнными параметрами отклоняется. После отправки клиент фиксирует номер и параметры без пароля, закрывает их редактирование и сохраняет запрос после перезагрузки страницы. Потеря ответа, неверный пароль при повторе, ограничение частоты и обычный HTTP-отказ не удаляют сохранённое действие. Оно снимается с повтора после успеха либо серверного подтверждения, что команда с этим номером записана как отклонённая. `finance_admin_audit` и финансовые корректировки защищены от изменения и удаления триггерами. Пароли и сервисные секреты в журнал не попадают.

## Настройка и выпуск

Одинаковый `FINANCE_ADMIN_ACCOUNT_IDS` передаётся игровому, платёжному, Nile и, при использовании, прямому mainnet-сервису. Публичный API не получает платёжные ключи, пароли базы или приватные ключи кошельков. Денежные команды остаются внутри существующих сервисов с подписанным транспортом NOWPayments и закрытыми Unix-сокетами Nile/mainnet. Права игры на финансовые таблицы не расширяются.

Для существующего сервера добавить UUID владельца в серверную конфигурацию без замены `.env`, сохранить прежние Compose overrides, образы, исходники и постоянные тома. Следовать `AGENTS.md` и `deployment/SERVER.md`, сначала отправить исходники в main. После появления корректировок старые финансовые программы не понимают новый вид события: при откате интерфейса финансовый сервис с поддержкой `adjustment` сохраняется. Актуальную базу нельзя заменять старой копией после новых операций.

## Проверки

`npx tsc --noEmit`, `npm run check:finance`, `npm run build`.

`node --import tsx scripts/database-test.ts --import tsx --test server-tests/finance-admin.test.ts server-tests/finance/nile-pvp.test.ts server-tests/finance/nile-native-games.test.ts server-tests/finance/nile-atelier.test.ts`.

`npx playwright test --config playwright.admin.config.ts` собирает админку, запускает её preview, временную PostgreSQL и синтетический финансовый контур. Проверяет вход, фильтры, CSV, карточку, потерю ответа, неверный пароль и перезагрузку с повтором без второго начисления, подтверждённый отказ резерва, приостановку, историю, телефон и запрет доступа обычному игроку. Браузер обращается к настоящему API тестового контура. Тестовые аккаунты и средства не используются на production.
