# Улица казино

Улица является локацией `street` внутри общей комнаты. Выход находится в нижнем левом углу первого этажа, в точке `(180, 1300)`. После выхода персонаж появляется перед дверью казино. Кнопки «На улицу» и «В казино» ведут персонажа к физическому порогу, а сервер подтверждает переход. Мгновенного переноса по кнопке нет.

Вблизи показан плоский фасад с входом слева. Повторяемые секции стены продолжаются выше всех границ камеры. Крыши и последнего видимого этажа нет. Общий вид показывает только основание здания и улицу сверху, поэтому ни один масштаб не задаёт общее число этажей. Добавление будущих внутренних этажей не требует изменения основания или уличного маршрута.

Перед зданием, по двум сторонам и сзади есть связанный пешеходный проход. `src/shared/street.ts` задаёт единые препятствия для сервера, локального перемещения и сетевого предсказания. Фасад становится полупрозрачным при перекрытии персонажа. Изменение прозрачности мгновенное, без вспышек и дополнительной анимации; настройка уменьшенного движения сохранена. В режиме общего вида вместо фасада отображается плоский план.

Аккаунт, персонаж, чат, кошелёк и восстановление соединения остаются общими. Переход увеличивает прежнюю ревизию локации, поэтому задержанные команды с другого этажа отбрасываются. Во время игры, санкции или переноски кота переход блокируется прежними серверными правилами. Новых игр, выплат, ставок, покупок и звуков улица не добавляет. Охрана проходит через существующие связанные двери; сопровождение на улице использует уличную безопасную точку.

Проверки запускаются командами `npm run test:street` и `npm run test:street:ui`. Браузерная проверка использует собранное приложение, временную PostgreSQL и собственные порты 5191/2591. Проверяются выход, полный обход, возврат, перезагрузка на улице, сохранение комнаты и баланса, подключённый чат и отсутствие горизонтального переполнения на 1440x1000 и 390x844. Платные внешние API не используются.

Результаты и ограничения проверки находятся в [verification.json](concepts/casino-street/verification.json). Снимки реального приложения и принятый референс находятся рядом с отчётом. Это изменение исходников, публикация на production не выполнялась.

На этапе сверки SHA-256 действующего `arcadeCatalog.ts` совпал с веткой. Каталог, допуск к новым раундам, игровые пакеты и расчёты не изменены этой задачей. Действующий `cabinets.ts` отличается от исходного main и этой задачей не изменён. При отдельной подготовке публикации требуется штатная сверка production по `docs/release-process.md`, чтобы не включить посторонние изменения main.
