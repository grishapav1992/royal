# Граф знаний Рояля

Граф связывает возможности проекта, сервисы, интеграции, решения и результаты задач с их источниками. Его копия находится в проекте, серверная копия используется фабрикой ИИ. Аналитик, разработчик и тестировщик получают снимок графа вместе с существующим справочником проекта. В истории запуска записываются хеш снимка и число сущностей, связей и конфликтов.

Сервер работает независимо от ноутбука. Локальная копия и автоматический обмен обновляются, когда ноутбук включен, пользователь вошел в macOS и сервер доступен. При отсутствии связи остаются последние успешно полученные знания.

## Что используется

Это [Graphiti от Zep](https://github.com/getzep/graphiti), `graphiti-core` версии 0.30.2, с FalkorDB Lite. Проверенные структурированные записи переносятся в сущности, связи и эпизоды Graphiti. У эпизодов сохраняются ссылки на источники и историю изменений.

Извлечение фактов языковой моделью, смысловые embeddings и модельное ранжирование в этом сервисе выключены. Поиск использует текстовое соответствие BM25 и обход связей. Сервис не вызывает платный API и не требует ключей моделей. Работа ролей фабрики через существующий Codex остается отдельным процессом.

Журнал событий является источником состояния. База Graphiti представляет восстановимую проекцию журнала. Файлы базы между компьютером и сервером не копируются.

Текущий предел журнала: 20 000 событий и 8 MiB. При превышении обмен отклоняется целиком, существующая история сохраняется. Для большого долговременного архива потребуется расширить предел или добавить проверяемое архивирование. Лимит памяти серверного Graphiti составляет 384 MiB.

## Какие знания попадают в граф

- Проверенные факты из `ai-factory/project-knowledge/graph-seed.json`, сопоставленные со справочником `PROJECT.md` и документами проекта.
- Ответы владельца на вопросы задач. Они сохраняют принадлежность к исходной задаче.
- Подтвержденные результаты разработки и тестирования. Кандидат на выпуск хранится с отдельным статусом и не обозначает опубликованную возможность.
- Явно добавленные локальные сущности и связи с источниками.

Граф не читает автоматически все чаты Codex и не превращает каждое сообщение в факт. Новый подтвержденный функционал нужно отразить в документации и в проверенном наборе фактов. Ответы и подтвержденные результаты задач фабрика добавляет на сервере автоматически. Секреты, содержимое `.env`, ключи и авторизация Codex не являются источниками графа.

Статусы записей: `verified` (подтверждено), `decision` (решение), `candidate` (кандидат на выпуск), `planned` (план). Окружение указывается отдельно: `project`, `production`, `sandbox`, `testnet`, `candidate`. Это позволяет отличать тестовый шлюз, подготовленный код и возможность, уже работающую на сервере.

## Локальные команды

Команды запускаются из корня проекта. Нужны Node.js 24 или новее и отдельное Python-окружение `ai-factory/knowledge-graph/.venv`. Его зависимости закреплены в `requirements.txt`. Для настройки окружения используй доступный Python 3.12:

```sh
python3.12 -m venv ai-factory/knowledge-graph/.venv
ai-factory/knowledge-graph/.venv/bin/python -m pip install -r ai-factory/knowledge-graph/requirements.txt
node ai-factory/knowledge-cli.mjs init
```

Если окружение уже подготовлено, повторная установка зависимостей не требуется.

| Команда | Действие |
| --- | --- |
| `node ai-factory/knowledge-cli.mjs init` | Создать или обновить локальную проекцию из проверенного набора фактов и существующей истории. |
| `node ai-factory/knowledge-cli.mjs sync` | Один раз обменяться историей с сервером и обновить локальный Graphiti. |
| `node ai-factory/knowledge-cli.mjs watch` | Повторять обмен, делая паузу 60 секунд между попытками. Ошибка связи приводит к следующей попытке. |
| `node ai-factory/knowledge-cli.mjs status` | Проверить состояние локальной проекции Graphiti. |
| `node ai-factory/knowledge-cli.mjs search шлюз` | Найти сущности и связи в локальном графе. |
| `node ai-factory/knowledge-cli.mjs put /путь/record.json` | Добавить или изменить одну локальную сущность либо связь. |
| `node ai-factory/knowledge-cli.mjs resolve /путь/record.json` | Явно выбрать актуальную запись при конфликте нескольких версий. |

`init`, `put` и `resolve` меняют локальный граф. Чтобы передать изменения серверу, выполни `sync` или дождись фонового обмена. Поиск и состояние локальной копии доступны без связи с сервером.

Локальные данные находятся в `ai-factory/knowledge-graph/.state/`:

- `journal.json`: история событий, включая прошлые версии и разрешенные конфликты.
- `snapshot.json`: текущий снимок.
- `graph.rdb` и служебные файлы: локальная база Graphiti.
- `sync.json`: хеш и время последнего успешного обмена.
- `sync-service.log`: очищенный журнал фоновой службы, если она установлена.

Каталог состояния имеет права `0700`, файлы состояния и журнала службы имеют права `0600`. Локальное состояние и Python-окружение не нужно включать в исходники или переносить на сервер как базу данных.

## Как проходит обмен

Локальный исполнитель подключается к `root@45.192.12.242` через существующий ключ `~/.ssh/royal_server_ed25519`. Используется фиксированная команда обмена внутри `/opt/royal-ai`, без интерактивного входа. Приватный ключ остается на компьютере. Его содержимое, `.env` и файлы авторизации не копируются.

Обе стороны обмениваются событиями, идентификатор которых вычислен из содержимого. Повторный обмен не создает дубликаты. Старые версии сохраняются. После слияния сравнивается хеш снимка, затем обновляется локальная проекция. Время в `sync.json` означает последний успешно завершенный обмен и не подтверждает текущую доступность сервера.

Если один факт независимо изменен на обеих сторонах, сохраняются обе ветки и появляется конфликт. Конфликтующая запись исключается из текущего набора подтвержденных фактов. Система не выбирает версию по времени или стороне автоматически. Команда `resolve` создает новую запись, связанную с обеими ветками, и сохраняет историю решения.

Если содержание, источники, статус и происхождение двух актуальных версий полностью совпадают, объединяется только их история. Такое объединение повторяемо и не выбирает между различающимися фактами.

Задачи, ответы и результаты формируются серверной фабрикой. Пользовательским записям выбирай отдельные ID, например `custom:mainnet-rollout-plan`, чтобы не смешивать их с системными `task:`, `decision:` и `candidate:`.

## Формат собственной записи

Файл для `put` и `resolve` содержит один JSON-объект. Не добавляй поля снимка `event_id`, `created_at`, `hash` или `schema_version`: историю и контрольные суммы создает исполнитель.

Для сущности обязательны ровно эти поля:

```json
{
  "kind": "entity",
  "id": "custom:mainnet-rollout-plan",
  "name": "План запуска основной сети",
  "entity_type": "decision",
  "summary": "План: согласовать условия запуска основной сети. Подготовленный код еще не означает работающую интеграцию.",
  "status": "planned",
  "environment": "project",
  "evidence": [
    {
      "path": "ai-factory/project-knowledge/PROJECT.md",
      "sha256": "ЗАМЕНИТЬ_НА_SHA256_ИСТОЧНИКА"
    }
  ]
}
```

В примере нужно заменить `sha256` на 64 шестнадцатеричных символа контрольной суммы источника. Ее можно получить командой:

```sh
shasum -a 256 ai-factory/project-knowledge/PROJECT.md
```

Допустимые `entity_type`: `project`, `service`, `integration`, `mechanic`, `document`, `decision`, `task`, `candidate`.

Для связи обязательны ровно поля `kind`, `id`, `source`, `target`, `predicate`, `text`, `status`, `environment`, `evidence`. Значение `kind` равно `relation`; `source` и `target` содержат ID существующих сущностей. `predicate` начинается с латинской строчной буквы и содержит только строчные буквы и символ `_`, например `requires` или `implements`. Отсутствующие сущности не создаются автоматически.

ID состоит из латинских строчных букв, цифр и символов `:`, `_`, `-`, начинается с буквы или цифры и имеет длину до 200 символов. Список `evidence` обязателен, содержит от 1 до 8 объектов только с полями `path` и `sha256`. Путь относительный, без перехода в родительский каталог и ссылок на секреты. Указывай источник, действительно подтверждающий текст записи.

## Автоматический обмен в macOS

Установщик сначала создает проверяемый plist в `ai-factory/deployment/com.royal.knowledge-sync.plist`. В нем записаны абсолютные пути текущего Node, проекта и исполнителя. Вызов без аргументов не устанавливает службу:

```sh
node ai-factory/deployment/install-knowledge-sync.mjs
```

Чтобы установить и включить обмен:

```sh
node ai-factory/deployment/install-knowledge-sync.mjs --install
```

Служба `com.royal.knowledge-sync` устанавливается в `~/Library/LaunchAgents/` для текущего пользователя. Запускай установщик без `sudo`. Она регистрируется для немедленного запуска и запуска после входа этого пользователя в macOS. Фактическую работу подтверждают состояние `running` службы и новая запись `synchronized` в `sync-service.log`. Во время сна, выключения ноутбука или отсутствия сети новые данные не поступают в локальную копию. Серверный граф и фабрика продолжают работать независимо.

Фоновый исполнитель вызывает тот же `knowledge-cli.mjs watch`, начиная работу из домашнего каталога. В журнал синхронизации попадают только время, хеш, счетчики и обобщенный код ошибки. Сырой вывод ошибок дочернего исполнителя и содержимое записей не сохраняются. Размер журнала ограничен примерно 1 MiB; при достижении лимита журнал очищается. История знаний от этого не меняется.

Диагностика самого запуска находится отдельно в `~/Library/Logs/RoyalKnowledge/bootstrap.log` с правами `0600`. Этот путь и начальный рабочий каталог не требуют предварительного доступа фоновой службы к `Documents`. Служба не меняет разрешения macOS и не включает полный доступ к диску. Если macOS ограничивает чтение проекта, это остается явной ошибкой запуска, а не подтвержденным обменом.

Если проект или Node перемещен, повтори `--install`, чтобы обновить абсолютные пути. Установщик не перезаписывает конфигурацию, не принадлежащую этой службе. Если включение новой конфигурации не удалось, он восстанавливает прежний plist.

Для удаления фонового обмена:

```sh
node ai-factory/deployment/install-knowledge-sync.mjs --uninstall
```

Команда останавливает пользовательскую службу и удаляет установленный plist. Локальный граф, история и серверная система сохраняются.

## Просмотр на доске

Открой «Знания проекта» в панели команды. Там доступны поиск, связи, источники, конфликты, состояние Graphiti и время обмена. При недоступности графового сервиса панель показывает сохраненный снимок с явным сообщением о недоступности. Состояние готовности графа не означает, что подготовленный игровой код уже опубликован.
