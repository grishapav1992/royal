# Slot Primitive

Копируйте **только эту папку** в новый репозиторий. Она собирается без исходников, окружения и базы Royal. `src/index.ts` задаёт порт, `src/actions.ts` содержит фасад команд и событий, `src/view.ts` показывает подключение кнопок и поля, `src/demo-services.ts` подставляет готовые тестовые исходы. В Royal вместо стенда хост передаст свой `SlotServicesV1`.

Инструкции для агента, который оформляет или поддерживает игру, находятся в [AGENTS.md](AGENTS.md) и копируются вместе с шаблоном.

## Что нужно стороннему разработчику

Передайте **копию всей папки шаблона**, а не только собранный пакет. В копии есть `AGENTS.md`, фиксированные зависимости, стенд, сценарии и проверки. Для задачи на оформление приложите бриф: размеры доступного контейнера, схему барабанов и символов, список обязательных состояний, разрешённые ресурсы и сценарии приёмки.

| Уровень | Что нужно |
| --- | --- |
| Игровой код | TypeScript, браузерные HTML, CSS и DOM. У пакета нет зависимостей для исполнения. React, Phaser, сборщик, CDN и внешний API не обязательны. |
| Сборка и тесты | Node.js 22+, npm, закреплённый TypeScript. Playwright и его Chromium нужны только для браузерных проверок. |
| Ручной предпросмотр | Любая статическая раздача папки шаблона. В примере используется Python 3; при наличии встроенного предпросмотра он не нужен. |
| Компоненты | `src/index.ts` задаёт состояние и допустимые ходы, `src/actions.ts` даёт фасад команд и эффектов, `src/view.ts` и `view.css` дают поле и управление. `src/demo-services.ts`, `src/demo.ts` и конструктор линий нужны для разработки и не переносятся в игру. |
| Что предоставить для темы | Локальные изображения, звуки и шрифты с указанием происхождения. Карта символов и визуальных состояний, готовые снимки для проверок, стили внутри игрового корня. Анимация и звук необязательны для базовой вёрстки. |

Минимальный экран состоит из поля, редактора ставки, основной кнопки, статуса раунда и подтверждённых сумм. Блок выбора показывается только при доступном бесплатном действии, а восстановление должно быть явно отличимо от новой ставки. Персонаж, звук, эффект выигрыша и просмотр кадров можно добавлять отдельно. Конструктор линий в экран игрока не входит.

**Royal нужен только при интеграции.** Сторонняя копия не получает доступ к кошельку, авторизации, чату, базе, `.env`, правилам или API ставок. Она отправляет намерения через фасад и показывает подтверждённые данные из адаптера или моков. Не открывайте стенд с моками как часть зала.

## Запуск без бэкенда

Из корня шаблона:

```bash
npm ci
```

```bash
npm test
```

```bash
python3 -m http.server 4173 --bind 127.0.0.1
```

Откройте `http://127.0.0.1:4173`. Выберите сценарий: линии, ways с разной высотой, кластер и кадры каскада, удержание и респин, бонус со скаттерами, фриспином, множителем и выбором. В бонусе ответ на бесплатный спин намеренно теряется. «Проверить ход» возвращает результат той же партии, после чего становится доступен выбор символа. Стенд не использует деньги, не вычисляет выигрыши и не отправляет запросов в Royal.

### Браузерные проверки

Для автоматической проверки установите Chromium Playwright, затем запустите тест. Отдельный сервер для него не нужен:

```bash
npx playwright install chromium
```

```bash
npm run test:browser
```

Если уже установлен Chrome, можно использовать его вместо загрузки Chromium:

```bash
SLOT_BROWSER_CHANNEL=chrome npm run test:browser
```

## Конструктор линий

Укажите размер от 2 до 8 барабанов и рядов. Выберите по одной ячейке в каждом столбце. Линии можно добавить, изменить, удалить, скачать в JSON или загрузить обратно. Экспорт имеет тот же порядок координат, что и линии Royal: `paylines[i][column]` содержит номер ряда сверху, начиная с нуля. Например:

```json
{ "columns": 5, "rows": 3, "paylines": [[1, 1, 1, 1, 1], [0, 1, 2, 1, 0]] }
```

В сценарии «Линии» следующий спин читает сохранённую геометрию и подсвечивает первую линию на тестовых символах, даже если символы различаются. Это проверка визуала, не выигрыш. Конструктор предназначен для разработчика; он не меняет набор линий, правила или цену раунда на сервере.

## Как соединить механику с визуалом

Передайте `mountSlot` источник снимков, фасад команд и, при необходимости, обработчики эффектов. Этот способ одинаков для Royal и стенда:

```ts
const commands = createSlotActions(services, { bigWinMultiplier: 20 });
const effects: SlotPresentationActions<ReelView> = {
  win: ({ round }, signal) => showWin(round.view, signal),
  bigwin: ({ round }, signal) => showBigWin(round.view, signal),
};
const slot = mountSlot(root, services, commands, effects);
```

`showWin` и `showBigWin` принадлежат визуалу игры и не отправляют финансовых команд. `bigWinMultiplier` задаётся игрой как целый множитель от двух. Без него любой положительный итог обозначается `win`. Число 20 здесь приведено как пример из «Карибских сокровищ», а не правило шаблона.

### Команды и события

| `read().status` | Действие интерфейса |
| --- | --- |
| `spin` | Вызвать `commands.bet(текущий текст ставки)` на явное нажатие. `stakes.parse()` проверяет точность и диапазон. Не подставляйте прежнее значение. |
| `continue` | Показать `freeActions`. Вызвать `commands.playFree(round, action.id, picks)` с ID и ревизией показанного раунда. За обычный бесплатный ход выбор не передаётся. |
| `recover` | Вызвать `commands.recover()`. Royal повторяет сохранённую операцию с тем же UUID. Не отправляйте новую ставку. |
| `sync-required` | Предложить `commands.refresh()` для чтения состояния без новой ставки. |
| `busy`, `blocked`, `signed-out`, `unsupported-round` | Не отправлять ход. Для несовместимого активного раунда нужен совместимый интерфейс. |

`bet` и `free` также именуют события подтверждения соответствующих команд. `loss`, `partial`, `return`, `win` и `bigwin` приходят только для нового подтверждённого завершения оплаченного раунда. Они различают нулевую выплату, частичный возврат, полный возврат и положительный итог по полной стоимости раунда, даже если последний ход был бесплатным. **Эти события не начисляют деньги.** Ставка, исход и баланс принадлежат хосту. Денежные поля хранят строки целых центов; `balanceLabel` предназначен только для показа. На стенде суммы являются тестовыми, реального кошелька нет.

В `busy` показывайте нейтральное ожидание. При открытии, обновлении и восстановлении читайте снимок без повторного эффекта. Обработчики получают `AbortSignal`: отменяйте свои таймеры, звуки и анимации при его срабатывании. Эталонный `mountSlot` отменяет эффекты при паузе, скрытии, смене снимка, новом действии и закрытии. Отмена визуала не отменяет уже отправленный ход.

### Своя механика и оформление

`round.view` принадлежит игре. `ReelView` показывает форму поля, линии, удержание и кадры, но не классифицирует бонус или промежуточную комбинацию как окончательную выплату. Для эффекта пушки, скаттеров или другого специального события расширьте `View` и обработайте подтверждённый кадр в визуале. Покупка бонуса, платный респин и выбор оплачиваемого числа линий не входят в этот контракт.

Для новой темы обычно достаточно заменить `src/view.ts`, `demo.css` и ресурсы. Для новой механики добавьте тестовый сценарий в `src/demo-services.ts`. В Royal переносится визуал, а не мок. После сборки пакет экспортирует основной контракт и входы `./actions`, `./view`, `./view.css`, `./paylines`. При использовании готового поля подключите `view.css`: стили привязаны к корню `.slot-primitive`, а `demo.css` предназначен только для стенда. Подключение к Royal описано в `docs/slot-primitive.md` основного проекта.
