# Карта интерфейсов Primitive и Royal

Цель: один игровой экран получает снимки и отправляет намерения через один контракт. В автономном стенде адаптер использует сценарии; в будущем интеграционном стенде он обращается через прокси к тестовому Royal; в зале адаптер использует штатный хост. **Контракт экрана и сетевой интерфейс стенда не взаимозаменяемы.**

## Что существует сейчас

В автономном комплекте уже есть [порт снимков и сервисов](../src/index.ts), [фасад команд](../src/actions.ts), [пример экрана](../src/view.ts) и [локальные сценарии](../src/demo-services.ts). Адаптер `createRoyalSlotServices` и подключение «Пути дракона» относятся к отдельному прототипу Royal и в этот комплект не входят. **У автономного комплекта пока нет сетевого адаптера, тестового шлюза или выдачи доступа.**

### Что вызывает игровой экран

| Интерфейс | Назначение | Когда использовать |
| --- | --- | --- |
| `state.read()` | Синхронно прочитать последний доступный снимок | При монтировании, уведомлении и перед обработкой действия. Это не сетевой запрос. |
| `state.subscribe(listener)` | Подписаться на изменение снимка; возвращает функцию отписки | При монтировании. При уведомлении перечитать `read()`; на закрытии отписаться. |
| `state.stakes.defaultCents`, `presetsCents`, `parse(draft)` | Начальная ставка, пресеты и проверка текущего текста; результат разбора в целых центах либо `undefined` | Для поля ставки. Парсер не определяет исход и не подтверждает списание. |
| `commands.bet(draft)` | Намерение начать один обычный платный раунд | Только при `spin`, по явному действию или в подтверждённой серии автоигры. Передать текущий текст, не последнюю валидную ставку. |
| `commands.playFree(round, actionId, picks?)` | Бесплатное продолжение по показанным ID и ревизии раунда | При `continue`. Передать только действие и варианты из `freeActions`. Это не способ купить бонус. |
| `commands.recover()` | Проверить сохранённую потенциально принятую операцию | При `recover`. Адаптер повторяет прежний UUID и параметры, а не делает новую ставку. |
| `commands.refresh()` | Запросить состояние без совершения хода | При `sync-required` и при подключении, если это требуется адаптеру. Не заменяет восстановление. |
| `commands.subscribeFeedback(listener)` | Подписаться на подтверждённые события представления; возвращает функцию отписки | Для эффектов, звука и учёта подтверждённого старта. Не источник баланса и не подтверждение начисления сам по себе. |

Полный `SlotServicesV1<View>` нужен адаптеру: он реализует `spin`, `playFree`, `recover`, `refresh`, ставки и чтение состояния. Точка сборки передаёт сервис в `createSlotActions(services)`. Экрану передают только чтение, ставки и фасад команд, а не транспорт или авторизацию. Пример `mountSlot(root, state, commands, effects)` относится к эталонному интерфейсу на DOM; своя игра может иметь другой экран с теми же зависимостями.

### Как читать снимок

`SlotSnapshot<View>` содержит `status`, `round`, `freeActions`, `balanceLabel` и `error`. Подтверждённый `SlotRound<View>` содержит `id`, `revision`, `rulesVersion`, `state`, строки целых центов `stakeCents`, `spentCents`, `returnedCents` и данные представления `view`. `balanceLabel` служит для показа, его нельзя использовать как число для расчёта. Поля результата и денежные данные берутся из снимка; вычислять совпадения или выплаты по картинке поля нельзя.

| Состояние снимка | Что игрок видит и может сделать |
| --- | --- |
| `spin` | Ставка и главное действие; неверный черновик блокирует вращение. |
| `busy` | Нейтральное ожидание, прежнее или нейтральное поле. Не показывать неподтверждённый итог и не отправлять второй ход. |
| `continue` | Только доступные бесплатные действия и необходимые варианты выбора. Границы выбора находятся в `minPicks` и `maxPicks`. |
| `recover` | Отдельная кнопка «Проверить» и объяснение, что повторного списания не требуется. |
| `sync-required` | Обновление состояния без ставки. |
| `blocked`, `signed-out`, `unsupported-round` | Объяснение блокировки или несовместимости; платный ход недоступен. |

События `bet` и `free` подтверждают соответствующие действия. `loss`, `partial`, `return`, `win` и `bigwin` классифицируют только **итог всего оплаченного раунда**, а не промежуточный кадр, каскад или бесплатный спин. Обновление, восстановление и переоткрытие показывают подтверждённый снимок без повторного празднования. Обработчики эффектов используют `AbortSignal`; их отмена не отменяет принятую операцию.

### Подключение и жизненный цикл

| Слой | Действие |
| --- | --- |
| Стенд | Выбирает локальный адаптер или, после реализации, явно подключается к тестовому проекту. Передаёт экрану корневой элемент и зависимости. Меняет размеры контейнера, а не состояние раунда. |
| Точка входа Royal | Экспортирует `gameId`, `apiVersion`, `rulesVersion`, `progressVersion` и `mount(host, context?)`. Читает `GameHostV1`, проверяет совместимость, собирает адаптер и при необходимости задаёт название через `context.setTitle`. |
| Адаптер Royal для слота | `ordinaryStart(stakeCents)` задаёт допустимые настройки старта, `project(session)` переводит подтверждённый снимок в `View`, `freeMoves(session)` описывает поддержанные игрой бесплатные варианты. Привязка проверяется против разрешённых сервером ходов, ревизии и полной цены. |
| Игровой экземпляр | Возвращает `destroy()`. Если использует звук, длительные эффекты или автоигру, реализует `pause()` и `resume()` там, где хост их вызывает. На закрытии освобождает свои таймеры, подписки и ресурсы. Пауза не сбрасывает принятый раунд. |
| Хост Royal | Владеет окном и чатом, языком, общим звуковым выходом, учётной записью, транспортом и кошельком. Игра не создаёт их копии и не меняет оболочку глобальными стилями. |

Версии не следует объединять в одно поле: `apiVersion` относится к совместимости интерфейса хоста; `rulesVersion` закрепляет правила принятого раунда; `progressVersion` относится к совместимости представления или прогресса конкретной игры. Версия выпуска комплекта Primitive и версия будущего сетевого интерфейса обозначаются отдельно.

Вспомогательные методы не отправляют ставки: `formatCents` форматирует строки целых центов, `validFreePicks` проверяет набор выбранных значений, `paylineCells` переводит линию в позиции сетки. На стороне Royal точка сборки может передать переводы через `i18n.t` и настройки звука через `gameAudio.getPreferences()` и `onPreferences(listener)`. Они не являются сетевыми методами Primitive. Размер выделенной области экран получает из контейнера, например через `ResizeObserver`.

В других жанрах в Royal есть отдельные контексты. `context.pvp` при наличии даёт `get()`, `subscribe()`, `busy()` и `move()`, а согласование условий и серверное время доступны в поддерживающих их адаптерах. `context.activity` передаёт принадлежность комнате и её состояние, а экземпляр получает `update`, `updatePlayers` и уведомления о связи. Эти контексты **не входят в порт слота** и не выдаются описываемым тестовым API.

### Существующий транспорт Royal: справка для сопровождающего

`ExpansionClient.refresh()` читает `GET /api/demo-wallet/expansion`; `act()` создаёт UUID, а `retry()` повторяет сохранённую операцию через тот же `POST /api/demo-wallet/expansion`. Это внутренний транспорт хоста, а не интерфейс внешней игры. Сервер определяет аккаунт из сессии; заголовок привязки запроса к аккаунту сам по себе не выдаёт доступа. Внешний экран не вызывает эти маршруты напрямую.

```text
src/modules/GameHostContract.ts
src/modules/RoyalSlotServices.ts
src/wallet/ExpansionClient.ts
server/demoWalletRoutes.ts
games/panda-dragon/entry.ts
games/panda-dragon/wallet-binding.ts
```

## Предложение: сетевой интерфейс тестового стенда

**Это спецификация будущего шлюза `v1`, а не действующие маршруты.** Точная структура сообщений закреплена в [типах тестового контракта](../src/contract/sandbox-v1.ts) и [проверяемых примерах Panda Dragon](../src/contract/panda-examples.ts) и [Cosmic Escape](../src/contract/cosmic-examples.ts). **Основной образец: [Cosmic Escape](cosmic-brief.md).** Его экран использует локальный адаптер; сообщения будущего шлюза проверяются отдельно. Локальный прокси слушает только на компьютере разработчика и направляет допустимые запросы на заранее настроенный тестовый шлюз. Боевого адреса у него нет. Игровой экран по-прежнему использует методы из таблицы выше.

| Назначение | Предлагаемый метод | Данные и ограничения |
| --- | --- | --- |
| Подключение и проверка совместимости | `GET /primitive/v1/capabilities` | Тестовое окружение, проект и текущий тестовый счёт, разрешённые игры, совместимые версии правил и поддерживаемые команды. Не передавать серверные секреты. |
| Загрузка и обновление | `GET /primitive/v1/games/{gameId}/snapshot` | Только доступная игра и собственный тестовый счёт. Возвращает баланс и проекцию подтверждённого раунда, не делает ход. |
| Обычный старт | `POST /primitive/v1/games/{gameId}/operations` с `kind: 'start'` | `operationId` (UUID), `stakeCents`, ожидаемая `rulesVersion`, `settings`. У имеющегося примера Panda Dragon `settings: {}`, у будущего пилота Cosmic Escape `{ luelon: { mode: 'normal' } }`. Цена определяется на сервере. |
| Бесплатный ход | Тот же `POST` с `kind: 'free'` | `operationId`, `roundId`, `revision`, `actionId`, при необходимости `picks`. Шлюз проверяет владельца, ревизию, допустимые варианты и отсутствие цены у операции. |
| Восстановление | Тот же `POST` с исходными данными и тем же `operationId` | Ответ привязан к исходной операции. Новый UUID или изменённые параметры не являются восстановлением. |
| Справка для разработчика | Метаданные разрешённых правил в `capabilities` | Версия, диапазон и шаг ставок. Подробные правила и таблица выплат прикладываются к брифу, не рассчитываются в браузере. |

**Служебные действия находятся вне игрового экрана.** Владелец выдаёт и отзывает доступ к проекту и управляет тестовым балансом отдельным административным процессом. Стенд принимает выданный доступ вне исходников, проверяет соединение через `capabilities`, загружает первый снимок и только затем включает команды. При отключении останавливает запросы чтения и подписки, убирает доступ из текущего сеанса, но не стирает неразрешённую операцию и не восстанавливает её другим аккаунтом. Выпуск отдельных маршрутов входа, пополнения и сброса не требуется для ручной выдачи доступа в пилоте. Внешнему разработчику не передают боевые токены, cookies, сетевые заголовки Royal, чужие балансы или доступ к API пополнения и вывода. Сервер каждый раз проверяет разрешения, а не доверяет переданному ID счёта или локальному прокси.

### Снимки, подтверждения и ошибки

- `capabilities` возвращает `protocolVersion: 1`, `scope` и массив `games`. `scope` содержит `environment: 'sandbox'`, `sandboxId`, `projectId`, `accountId`; это серверно определённые значения, не поля запросов. `sandboxId` различает независимые тестовые среды и меняется, если переинициализация базы обнуляет нумерацию снимков. В каждой игре указаны ожидаемая `rulesVersion`, допустимые `commands` и политика `stakes`. Документация правил и выплат передаётся отдельно по брифу пилота, контракт `v1` не обещает отдельного маршрута таблиц выплат.
- `snapshot` возвращает `protocolVersion`, `scope`, `gameId`, `snapshotVersion`, `balanceCents`, `round` и `freeActions`. Суммы передаются каноническими строками неотрицательных целых центов: например, `"10"`, не `0.10`. `snapshotVersion` монотонен в рамках среды, проекта, счёта и игры. Более ранний снимок нельзя применять поверх позднего, даже если ID раунда изменился. `revision` внутри `round` относится только к этому раунду. `busy`, `recover` и другие локальные состояния определяет адаптер, а не сетевой снимок.
- Успешный `POST` возвращает `receipt` (`operationId`, `roundId`, `acceptedRevision`, `replayed`) и актуальный `snapshot`. Подтверждение относится к исходной операции: при повторе `acceptedRevision` может быть меньше текущей ревизии снимка. Адаптер сверяет среду, проект, счёт, игру и операцию. Переоткрытие или восстановление не повторяет визуальные события результата.
- Бесплатное вращение Panda Dragon принимает ревизию `1` без `picks`, а выбор награды принимает `2` и ровно один вариант `[2]` или `[3]`. Сервер разрешает ход только по собственному актуальному состоянию. Клиент не передаёт ID счёта, баланс, стоимость бесплатного хода или рассчитанную выплату.

| Ответ | Код в теле | Что делает адаптер |
| --- | --- | --- |
| `400`, `409` либо `422`, операция достоверно не принята | `invalid-operation`, `stale-round` либо `insufficient-funds` соответственно, `disposition: 'rejected'` | Считать отказ окончательным только для коррелированного `operationId`, по которому сервер подтвердил отсутствие принятой операции. Показать причину. |
| `409`, тот же UUID с другими параметрами | `operation-conflict`, `disposition: 'unknown'` | Не отправлять новый платный ход. Такой конфликт не опровергает уже принятый исходный запрос. |
| `400`, `401`, `403`, `409` либо `503`, подтверждения нет | `invalid-request`, `unauthorized`, `forbidden`, `incompatible` либо `unavailable` соответственно, `disposition: 'unknown'` | Не считать операцию непринятой. Предложить восстановить доступ или совместимость. Сохранить уже отправленный запрос для восстановления. |
| Таймаут, потеря или непроверяемый ответ | Подтверждённого сообщения нет | Считать исход неизвестным. Не показывать новую ставку до разрешения операции. |

Ошибки несут `protocolVersion`, `code`, `disposition` и, когда запрос можно соотнести с операцией, `operationId`. Они не возвращают чужой снимок или область доступа. Одного HTTP-кода или текста ошибки недостаточно, чтобы объявить отсутствие списания.

### Повтор и границы

- Перед отправкой сохранить исходный запрос в контексте среды, проекта, счёта и игры. Учётное подключение закреплено за одним тестовым счётом. Перед повтором сверить сохранённый контекст с текущим и не пересылать запрос под доступом другого счёта или среды. При восстановлении передать тот же UUID и неизменные параметры. Проверка повтора на сервере предшествует проверке текущей ревизии для нового хода. Если первый запрос принят, повтор не даёт второго списания, а `replayed` равен `true`. Если первый запрос не дошёл, повтор может принять эту же операцию впервые. Поэтому кнопка означает повтор ранее отправленного хода, а не чтение без изменений.
- Тестовый шлюз вызывает штатный движок и виртуальный кошелёк тестового Royal, не реализует вторую математику. Отдельная база не содержит боевых данных; отсутствуют боевые платежи и запасной маршрут к ним. Ограничения запросов и журналы не должны раскрывать токены или персональные данные.
- Платные бонусы, ставки между игроками, общий пул, прогресс и синхронная игра не входят в `v1`. Для каждого нужен отдельный контракт и проверка совместимости. Описание жанра в [указателе концептов](concept-index.md) не означает поддержку шлюзом.

После сборки шаблона примеры можно вывести в JSON:

```bash
node --input-type=module -e 'import {cosmicExamples} from "./dist/contract/cosmic-examples.js"; console.log(JSON.stringify(cosmicExamples, null, 2))'
```

Команда `npm test` проверяет типы и связность примеров. **Она не валидирует произвольные сетевые ответы и не проверяет работающий шлюз, списания или авторизацию.** Проверки реального подключения ниже относятся к более поздним этапам.

## Проверка первого подключения

1. На чистой копии запустить сценарий без доступа к Royal; затем явно переключиться на тестовый режим и сверить разрешённую игру и версию.
2. В Cosmic Escape проверить ровно `0,10` за обычный раунд на все 20 линий, естественный бонус, бесплатную серию через `luelon-spin` по актуальной ревизии без `picks` и подтверждение итога. Платные миссии в этот пилот не входят.
3. Потерять ответ после принятия старта, переоткрыть экран, повторить ту же операцию. Убедиться: один дебет, сохранённые правила раунда, без повторного эффекта результата.
4. Проверить двумя тестовыми аккаунтами, что недоступны чужие снимки, ходы и восстановление. Проверить отзыв доступа и несовместимую версию до ставки.
5. Собрать импортированный экран штатным загрузчиком Royal с подключённым чатом. Режимы стенда, моки и прокси не должны входить в пакет модуля.
